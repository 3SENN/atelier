# Atelier feature spec

This is the detailed behaviour spec for every Atelier surface, with the status of each item.
Light and dark mode are required for every surface; nothing counts as done until it has been checked in both.

**Status:** ✅ done · ◐ partial (the item says what is missing) · ○ missing. The visual system is in [design-spec.md](design-spec.md), the screen-by-screen walkthrough in [ux-plan.md](ux-plan.md) and packs in [packs.md](../packs.md).

**Decisions this spec relies on:**
- Atelier needs no backend to work: where a server would otherwise be needed, it uses a local equivalent (export and import files, built-in presets, and settings stored locally per profile).
- The sidebar layout is the default, and the horizontal strip stays as the alternative layout.
- ⌘S shows or hides the sidebar, so Save Page As has no shortcut. It lives in the File menu and the main menu.
- One voice key, ⌥Space. While Atelier is focused, holding it is hold-to-talk. With the opt-in global launcher on, pressing it in another app toggles the launcher. Atelier registers the global shortcut only while none of its windows is focused, so key-up still reaches Atelier when it is in front.
- Labels: the sidebar's integrations row is **Connectors**, and the tools the agent builds are **Apps**. The guides page is **Guides**, and the full chat list is **All chats**.
- Speech goes through the native helper (`native/speech`), and logins go into Atelier's vault (`src/main/passwords/vault.ts`).

**Behaviours to keep from regressing:**
- ⌘W never closes the main window's active tab while a popup window is focused, and the File menu has Close Window ([SH-26](#sh-26)).
- ⌘D on a saved page opens the bookmark editor; it never silently removes the bookmark ([SH-49](#sh-49)).
- On atelier:// pages, ⌘R, zoom and DevTools act on the atelier:// page, never on a hidden web page underneath.
- Tabs never run off the window edge: once they reach their minimum width, the strip scrolls ([SH-21](#sh-21)).
- ⌘-click and middle-click on the bookmarks bar open the tab in the background.
- Each tab keeps its own find bar state, so switching tabs never loses the query ([SH-44](#sh-44)).
- Page full screen fills the window instead of staying inside its pane ([SH-05](#sh-05)).
- Clearing all history and deleting a chat, skill, routine, memory file or connector ask for confirmation first ([OV-09](#ov-09)).
- The window background follows the theme, so dark mode never flashes light at start-up or while resizing.
- The in-page agent overlay takes its colours from the theme and its badge text from the app language ([OV-04](#ov-04)).

## Shell

### Window and layout

- <a id="sh-01"></a>✅ **Sidebar and horizontal layouts.** Windows open in the sidebar layout: tabs, chats and destinations sit in a vertical sidebar. The current horizontal strip is kept as the alternative, chosen by a stored layout setting. An unknown value falls back to the sidebar. Settings › Appearance and the View menu switch layouts live in every window without reloading tabs. Pinning, groups, the context menu, previews and drag work in both layouts.
- <a id="sh-02"></a>✅ **Show or hide the sidebar.** A toolbar button and ⌘S (sidebar layout only) toggle the sidebar, and each window saves its own state. While the sidebar is collapsed, the button shows a dot when chats are unread or need input. Showing and hiding run as one transition ([DS-19](design-spec.md#ds-19), [DS-84](design-spec.md#ds-84)): the sidebar slides away while the sheet and the page views move in step, and Reduce Motion makes it instant. On macOS the window controls sit in the sidebar header, travel with it and are hidden while it is collapsed, so the toolbar has no inset; native full screen manages them itself. The controls never overlap other controls at any width.
- <a id="sh-03"></a>✅ **Resizable sidebar.** A handle on the sidebar's edge resizes it live from 220 to 360 px (default 300, about a fifth of the window; [DS-04](design-spec.md#ds-04)), and page views reflow on every step. The width is saved on release. Esc during a drag restores the old width, double-click resets it to the default, and arrow keys resize a focused handle in small steps. There is no animation under reduced motion. When the content card would get too narrow (below about 600 px with the panel open), the sidebar hides itself, and it comes back when there is room.
- <a id="sh-04"></a>✅ **Edge reveal.** Page views cover the chrome, so a CSS hover zone over a page never fires. While the sidebar is hidden, main polls the cursor (about every 40 ms, only then) and tells the chrome when the pointer reaches the left edge: up to 6 px inside the window, or up to 32 px outside it, so a window short of the screen's edge still reveals when the pointer stops at the screen's edge. The revealed sidebar floats above the page in the overlay view.
- <a id="sh-05"></a>✅ **Full-screen layout state.** When a page enters HTML full screen (`enter-html-full-screen`), the window switches to a chromeless state: the sidebar, toolbar and panel hide and the page view fills the window. Leaving restores the layout. Focus mode reuses this state. The notice is [OV-13](#ov-13).
- <a id="sh-06"></a>✅ **Window title.** The native window title follows the active tab's title, or the window's custom name, so the Window menu, Mission Control and the Dock list stay meaningful.
- <a id="sh-68"></a>✅ **Responsive from 900 to 1920 wide.** Every page (the new-tab page, each atelier:// page and Settings page, a chat page and a chat in the side panel) lays out at 900, 1280, 1470 and 1920 px wide and at 1280 with the side panel open, in light and dark: nothing overflows the window, clips its text, overlaps a neighbour or scrolls sideways. The layout group of the smoke test (`ATELIER_SMOKE_ONLY=layout`, `src/main/smokeLayout/`) audits every page at every size in the chrome's DOM, writes the findings to `layout-report.json` with a screenshot per page, and fails on any finding.

### Sidebar

- <a id="sh-07"></a>✅ **Destination rows.** The top of the sidebar lists Atelier destinations: All chats, Routines, Skills and Connectors. Meetings, Guides and other pages join them as rows. Each row opens its atelier:// page and reuses one tab per destination. Clicking the active destination again returns it to its root view and clears its search. Rows show live status: a countdown to the next routine run (with an upcoming-runs popover on hover) and an unread dot when a routine result arrives; a recording dot on Meetings; and unread and needs-input dots (never counts) on All chats, whose right-click menu marks everything read. Rows activate on pointer-down, and the selected one is the raised neutral chip ([DS-09](design-spec.md#ds-09)). Hidden destinations collect in an overflow row that ends with a link to sidebar options.
- <a id="sh-08"></a>✅ **New Tab row.** At the top of the sidebar, under the pinned grid and above the destinations, in the strong tone ([DS-06](design-spec.md#ds-06)). It adds the tab at the top of the list, below the pinned tiles, in both sort modes.
- <a id="sh-09"></a>✅ **Sidebar options.** A header button opens options with: a show/hide checkbox for each destination and section; the sections mode (tabs and chats, or tabs only); the chat sort (recent, manual or by progress, where progress is offered only when both sections show); the tab sort (manual or recent activity); and whether chats and tabs show how long ago they were used. The choices are stored locally per profile and apply live. The options draw in the overlay layer above the page ([DS-96](design-spec.md#ds-96)); while the sidebar floats over the page, or if the overlay can't open, they draw inside the sidebar's own bounds.
- <a id="sh-10"></a>✅ **Pinned tabs.** Pinned tabs are a grid of favicon tiles above the list. One or two tiles take one or two columns; more take three or four, whichever balances the rows. Dragging a tab into or out of the grid pins or unpins it, and the drag preview shrinks to a tile. A tile's close control unpins instead of closing, and tiles show loading, audio and attention states. Pinned tabs are stored locally, survive restarts and are shared by every window of a profile. Bulk close actions skip them.
- <a id="sh-11"></a>✅ **Chats section.** A collapsible section of open chats. These are tab-like entries: closable, ordered, previewable and counted by ⌘1–8, while the full history lives in All chats. The header has search and new-chat buttons and a Clear that takes every unpinned chat out of the sidebar (they stay in All chats; the toast's Undo puts them back in their order); its context menu also deletes them all after a confirmation. The section has an empty state. Each row shows its companion's avatar and a badge for working, needs approval or input, unread result or finished. Pinned chats sit on top. A draggable divider between Chats and Tabs sets how many rows show: arrows step one row, Home shows one, End shows all, double-click toggles between the default and all, and Esc cancels a drag. Hidden rows are summed up as a count with unread and needs-input badges, plus a link to All chats. A chat that is open as a page tab highlights its row instead of appearing twice. Rows open the chat context menu ([CH-47](#ch-47)), which has a bulk version for several selected chats.
- <a id="sh-12"></a>✅ **Tab order.** Tabs keep your drag order by default, or sort by recent activity with groups moving as blocks. In activity mode a drop records a placement override instead of a plain move. Entries created in the background, such as routine chats, wait to reshuffle until the pointer leaves the sidebar or has been still for about 10 s. Empty and private-window states have their own labels.
- <a id="sh-13"></a>✅ **Tab list scroll cues.** The list fades at its top and bottom edges when it can scroll. When the active tab, or one that needs input, is out of view, a small badge at that edge scrolls to it smoothly, and activating a tab scrolls it into view.
- <a id="sh-14"></a>✅ **Background context menu.** Right-clicking empty sidebar or strip space opens a native menu with: new tab, reopen closed tab, bookmark all tabs and close all tabs (the same as the tab list's Clear: every unpinned tab, with Undo in the toast); a layout submenu (sidebar or horizontal, show sidebar, toggle the companion panel, new chat beside the page); an appearance submenu (system, light, dark, and a link to Appearance settings); and rename this window. Items show their shortcuts and are disabled when they don't apply.
- <a id="sh-15"></a>✅ **Drag and drop in the sidebar.** Rows drag within and between typed zones (pinned grid, chats, groups, ordinary tabs), and each entry type declares which zones it may enter. Other rows slide aside to open a gap, and a drop settles in about 120 ms. Whole groups can be dragged, and inputs and buttons inside rows never start a drag.
- <a id="sh-16"></a>✅ **Sidebar footer.** The profile row shows the initial of your locally set name, plus a warning chip linking to Settings › Model and key when no API key is set. Clicking it opens the main menu ([SH-54](#sh-54)). On the right, an Update pill appears when an update is downloading, ready or failed ([UP-02](#up-02)).
- <a id="sh-17"></a>✅ **Media card.** While a background tab plays audio or video, a small sidebar card shows that page with go-to-tab, play/pause, mute and dismiss. Pausing from the card remembers the tab so the card can resume it. The card hides while that tab is active, and a setting turns it on.

### Tabs

- <a id="sh-18"></a>✅ **Tab row interactions.** Click activates. ⇧-click extends a range selection from the active tab, ⌥-click opens the tab in split view with the active one, middle-click closes, and right-click opens the tab menu. Enter or Space activates, and ⇧Enter or ⇧Space extends the selection. A split pair is one row showing both pages, with a separate-pair action instead of close. Rows show agent-control (with the companion's avatar), audio or muted, needs-input and finished badges.
- <a id="sh-19"></a>✅ **Tab context menu.** A native menu that adapts to the selection count. It offers: new tab next to this one and reopen closed tab; open in split view, with a submenu of recent tabs (direct when exactly two tabs are selected), or separate a split; add to a new or existing group, or remove from its group; move to a new window (only with more than one tab); reload, duplicate, copy link, pin or unpin, and mute or unmute site; bookmark or edit bookmark, with a folder submenu; and close, close others, close below and close all unpinned. Bulk items show counts, close items never touch pinned tabs, and a split row gets a submenu for each page.
- <a id="sh-20"></a>✅ **Tab navigation shortcuts.** Next and previous tab (⌥⌘→/⌥⌘← and ⇧⌘]/⇧⌘[) wrap around the visible order: pinned tiles, then chats, then tabs, skipping tabs in collapsed groups. ⌘1–8 select the nth visible entry and ⌘9 the last. ⌃⇧PageUp and ⌃⇧PageDown move the active tab one place.
- <a id="sh-21"></a>✅ **Horizontal strip.** Pinned tabs are icon-only at the leading edge, and other tabs shrink from about 200 px to about 20 px. Once they don't fit, the strip scrolls horizontally and keeps the active tab in view: it jumps when the tab is far away and scrolls smoothly when it is near. Rows behave as in the sidebar. Tabs show audio playing or muted (click to toggle), attention, agent-control, unread and split-pair indicators, and a new-tab button follows the last tab.
- <a id="sh-22"></a>✅ **Number hints.** Holding ⌘ alone for about 300 ms shows 1–8 badges on the first eight entries, the ⌘1–8 targets, in every window. Pressing another key, releasing ⌘ or the window losing focus hides them. Main watches key state in both the chrome and the page views, because a focused page doesn't pass key events to the chrome.
- <a id="sh-23"></a>✅ **Tab groups.** A group is a labelled header with its tabs inside: a chip in the strip, a row in the sidebar. Click, Enter or Space collapses or expands it. Renaming is inline (Enter commits, Esc cancels), and a new group starts in rename mode. Groups use a small set of colours, tuned for light and dark. Hovering a collapsed group shows a card listing its tabs. Groups have a name and a colour only, no icon.
- <a id="sh-24"></a>✅ **Group context menu.** Collapse or expand, rename, change colour, new tab in the group, ungroup (the tabs stay), and close the group, with its tab count.
- <a id="sh-25"></a>✅ **Multi-select tabs.** ⇧-click, ⇧Enter or ⇧Space selects a range from the active tab, and ⌘-click toggles single tabs. The selection drives bulk pin, mute, reload, duplicate, group, bookmark, move and close, and ⌘W closes the whole selection. Activating a tab normally clears the selection.
- <a id="sh-26"></a>✅ **Close order for ⌘W.** ⌘W closes, in order: a focused popup window, then an open peek, otherwise the selected tabs or the active tab. Rapid repeats are combined so one press never closes more than one target. Closing the last tab leaves a fresh new tab, and focus returns to the most recently used tab.
- <a id="sh-27"></a>✅ **Reopen closed tabs and windows.** ⇧⌘T reopens the most recently closed tab, window or chat into the current window, with its history and position. With nothing to reopen it beeps, and the menu items are disabled. History › Recently closed lists the last 10, with windows labelled by tab count.
- <a id="sh-28"></a>✅ **Tab hover preview.** Hovering a tab for about 300 ms shows a card about 260 px wide with a cached thumbnail (`capturePage`), the title and the domain. Once a card is open, moving to another row glides it there. Chat tabs and chat rows show the chat's kind (chat, routine run, agent task), the latest request and its source, a reply snippet, progress, up to three pending items (approvals, questions, hand-offs) plus a count, and the next scheduled run. Split pairs show both pages, collapsed groups list their tabs, and the Routines row lists up to eight upcoming runs plus a count (click one to open it). With the sidebar the card sits to the right of the row; with the strip, below the tab. It hides shortly after the pointer leaves, stays while the card itself is hovered, and closes on drag, a press, a tab switch or a space switch. It is drawn in the overlay view, and its exit animation has a one-second safety timeout.
- <a id="sh-29"></a>✅ **Recent-tab switcher.** ⌃Tab and ⌃⇧Tab cycle up to eight tabs in most-recently-used order, shown as thumbnail cards in up to four columns, with split pairs as one card and chats with their icon. The overlay appears only if Control is still held after about 150 ms, so a quick tap just flips to the previous tab. Releasing Control or pressing Enter commits, and Esc, a click outside or the window losing focus cancels. Hovering selects a card after a small pointer movement. Pages can't intercept the shortcut.
- <a id="sh-30"></a>✅ **Tear-off, move and drop to split.** Dragging a tab out of the list shows a floating ghost (a pre-created, click-through window above full-screen windows) that grows from a chip into a page thumbnail as you pull further away. The drop point decides the result. Back on the list it reorders, and on another window it moves the tab there. On a split zone over the content it opens beside the active page, and anywhere else it opens a new window at that point. Left and right split zones appear over the content card, pull toward the cursor and grow when in reach. They are disabled, with the reason shown, when the view is already split, the agent controls the tab or a chat is still replying. If the dragged tab was active, the source window falls back to its previous tab.

### Toolbar and address field

- <a id="sh-31"></a>✅ **Back, forward and reload.** Tooltips show the shortcut. ⌘-click opens the result in a new tab, and a long press (about 400 ms) or right-click lists that direction's history. ⇧-click on reload bypasses the cache, and ⌘-click opens a copy in a new tab. The reload icon animates while loading, then the button becomes Stop.
- <a id="sh-32"></a>✅ **Toolbar actions.** The right cluster is contextual ([DS-24](design-spec.md#ds-24)): empty on chat and app pages. On websites it holds a chat-about-this-page button that toggles the side panel (⌘J) and carries the working and approval indicators, then extension buttons. Split view shows only while the view is split (with the focused side). While a chat shows pages beside it, a thin divider and that chat's pages with expand and hide follow. Downloads live in the sidebar header in the sidebar layout ([DS-05](design-spec.md#ds-05)): only while there are downloads, a brief highlight for a new one and a thin progress bar (they stay in the toolbar in the horizontal layout). There is no companion button or avatar in the toolbar: the profile card opens from the chat header, chat rows and reply avatars. Private windows show a small private label. The meeting prompt and open-in-app suggestion appear only when relevant.
- <a id="sh-33"></a>✅ **Compact address pill.** When you aren't editing, the centred pill shows the host without www, shortening very long hosts in the middle. If the URL has a path, query or fragment, it adds a slash and the page title. atelier:// pages show a breadcrumb (Chat / title, Settings / section). The new tab shows a placeholder, and plain http (except localhost) or a bypassed certificate shows a not-secure marker. A site-info button sits inside the pill on the left and the bookmark star on the right; both are hidden on atelier:// pages. A zoom chip appears when zoom isn't 100% ([SH-38](#sh-38)). Click, Enter or Space edits the pill in place with the full URL, with suggestions below it ([SH-35](#sh-35), [DS-23](design-spec.md#ds-23)). The right-click menu has copy address, paste and go, edit, and the full-URL checkbox.
- <a id="sh-34"></a>✅ **Full-URL option.** A checkbox in the address field's context menu, mirrored in Settings › Appearance, makes the pill show the full URL. It is a local setting, off by default.
- <a id="sh-35"></a>✅ **Suggestions and the command bar.** The command bar (⌘L, ⌘T) is a centred palette in the overlay view. It groups: what you typed (as a search or a URL), top hits, an ask-the-companion row, search-engine suggestions (optional, because they send keystrokes to the engine), open tabs (switch to tab, with pinned tabs ranked higher), bookmarks, history and commands. Matched text is highlighted, and history rows can be removed. Inline completion fills a URL only for strong candidates (three or more visits in a week, often typed, or picked for this same query in the last day) and tolerates one typo. Unfinished text is kept per tab, and navigation errors show inline.
- <a id="sh-36"></a>✅ **Address editor keys.** Tab and ⇧Tab cycle suggestions, including the ask row. On an empty new tab, Tab moves focus to the page's ask field instead, with a hint. Up and Down move, and Up from the first row restores what you typed. → at the end of the text or ← accepts the completion, and → on an untouched field reveals the full URL for editing. Enter opens the selection or top match, and ⌘Enter or ⌘-click opens it in a background tab. Esc closes and restores the address. ⌘C copies a URL-aware value, ⌘A includes the completion, and typed hosts get https (http for local hosts).
- <a id="sh-37"></a>✅ **Site info.** The pill's site-info button opens a popover with: connection security and certificate details (subject, issuer, validity, protocol, fingerprint); this site's permissions, each changeable, with unset ones in a collapsed group; devices granted to the site, each revocable; the site's ad-blocking switch; clear site data (with a cookie count) and clear cache (with its size), both of which reload the page; and a link to full site settings. Esc or an outside click closes it.
- <a id="sh-38"></a>✅ **Zoom chip.** When a page's zoom changes, a percentage chip rolls into the pill. It stays visible while zoom isn't 100%, and clicking it opens a small popover with minus, plus and reset.

### New tab

- <a id="nt-01"></a>✅ **Search the web from a new tab.** The start composer keeps the companion first and adds a compact two-option switch at the left of its action row: ask the companion, or search the web with the default engine from Settings › Search (its name and a drawn letter mark, never a fetched favicon). The choice is remembered per profile (`newTabMode`). Anything that looks like an address always offers "Go to ‹host›" first and Enter goes there in the same tab. In web mode Enter searches in the same tab and ⌥Enter asks the companion; in companion mode Enter asks as before and a visible "Search ‹engine›" row runs on ⌥Enter. While typing, the command bar's own rows (top hits, open tabs, bookmarks, history, and engine suggestions only when Settings › Search allows them) list under the composer; ↑/↓ move, Enter runs the selected row, Esc clears. Searches and sites commit through the same path as the address bar. If no engine has been chosen yet (`searchEngineChosen`), setup's layout step offers the choice once (skippable), and so does the first switch to web mode on a new tab; Esc or "Keep ‹engine›" keeps the current one. The getting-started item "Search the web from a new tab" ticks on the first search or typed site from a new tab, and its card opens a new tab in web mode. Every engine Settings › Search lists now survives a restart (the saved-settings check knew only three). *Files:* `components/newtab/{StartSearch.tsx,useStartSearch.ts,searchLogic.ts,startSearch.css}`, `NewTabPage.tsx`, `StartComposer.tsx`, `pages/welcome/steps.tsx`, `main/features/address.ts`, `shared/firstWeek.ts`. *Tests:* `tests/newtab-search.test.ts`; smoke `src/main/smokeBrowser/newTabSearch.ts`.

### Split view and peek

- <a id="sh-39"></a>✅ **Starting split view.** Split view starts from: the tab menu (with a submenu of recent tabs); exactly two selected tabs; ⌥-clicking a tab; dropping a tab on a split zone; a link's context menu; or the agent opening a page beside the current tab. Left and right follow the tabs' order in the list, and the pair takes one entry.
- <a id="sh-40"></a>✅ **Split view menu.** The toolbar split button opens a small menu: swap sides; reset to even widths (disabled when already even); close the left or the right page, each listed with its favicon and title (the other page becomes a normal tab); and separate into two tabs. Arrow keys move between items and Esc closes. The menu also closes on window resize or blur, a click elsewhere, or when the split ends.
- <a id="sh-41"></a>✅ **Split seam.** The seam between split panes drags, and it uses the same seam component as the companion panel ([CH-03](#ch-03)). A focused seam moves with the arrow keys (⇧ for bigger steps), double-click resets to even widths, and Esc cancels a drag. Split ratios are saved with the window layout. An optional haptic tick marks a snap.
- <a id="sh-42"></a>✅ **Empty pane chooser.** An empty split pane lists this window's tabs that aren't already showing, plus a close-pane action. If every tab is visible, it says so.
- <a id="sh-43"></a>✅ **Peek.** Peek shows a link in a modal card over a dimmed page. It opens from ⇧-click, a link's context menu, links in companion replies and the pages a chat uses; only web, atelier and file links qualify. Esc, ⌘W or a backdrop click dismisses it, and focus returns to where it was. It scales in unless reduced motion is on. The header shows the domain and path with a lock for https, expands on click to a read-only, selectable full URL, and has open-as-tab and close. Pages a chat keeps are hidden rather than closed, so the chat can reuse them. Peek can't open during page full screen, a peeked page can't go full screen, and peek closes if its page moves to another window.

### Find, zoom and links

- <a id="sh-44"></a>✅ **Find bar.** ⌘F opens a floating find field about 400 px wide at the top right of the content card, drawn above the page. Each tab keeps its own open state and query. The field starts with the current selection (single line, up to about 250 characters, never from password fields), searches 60 ms after typing, and shows a searching state, current/total, and previous and next buttons. Enter/⇧Enter and ⌘G/⇧⌘G step through matches from anywhere, and Esc closes while keeping the match selected. Chat pages search the conversation instead ([CH-37](#ch-37)).
- <a id="sh-45"></a>✅ **Page zoom.** ⌘+ (and ⌘= with or without ⇧), ⌘- and ⌘0 zoom in 10% steps. The level is remembered per host, stored locally per profile (private windows keep it in memory only) and applied to every tab on that host, and these keys always go to the browser. On atelier:// pages the same keys scale the interface instead ([ST-27](#st-27)). The main menu has a zoom row with minus, plus, the percentage, reset and full screen.
- <a id="sh-46"></a>✅ **Link URL bubble.** Hovering a link shows its URL in a small bubble at the bottom left of the content card. It is at most 90% of the card's width, truncates long URLs in the middle and fades in and out. It follows the app theme, shows Atelier pages in their clean atelier:// form, and stays hidden while the page loads. Atelier draws it in the overlay view from the `update-target-url` event, not inside the page. Holding ⌥ while hovering turns it into the link preview card.

### Media

- <a id="md-01"></a>✅ **Now playing.** While any tab plays sound or video, or holds media it was playing, a toolbar button (bars that sway while something plays, held still under reduced motion; a count when there are several) opens a popover listing every source of the window and of the profile's other windows, playing ones first and newest first. Each shows its Media Session artwork (else the site's icon), title, artist and site, with previous and next when the page handles them, play or pause, playback speed, picture-in-picture for videos, mute and dismiss; the artwork or title goes to the tab, in whichever window holds it. Muted autoplay never counts. The sidebar card ([SH-17](#sh-17)) now shows the newest source that isn't showing with the same artwork and transport, and opens the popover when there are more. A page helper in every frame (embedded players too) reports the lead media element and the page's Media Session; its handlers are reached through a small wrapper in the page's world, never on account sign-in pages. Settings › Appearance › Media turns the button off.
- <a id="md-02"></a>✅ **Automatic picture-in-picture, sharper.** [ST-29](#st-29) now asks the page helper: a video playing with its sound on moves into the floating player even during a quiet passage, while audio alone, muted video, a page that forbids picture-in-picture or one already floating stay put. Without a report, Chromium hearing the tab still decides. It returns when you come back.
- <a id="md-03"></a>✅ **Playback speed and the media menu.** Every source's speed is 0.5× to 3× from the popover. Right-clicking a video or audio element adds Playback speed, Loop, Show controls, Picture in picture (videos), Open in new tab, Save as… and Copy address.
- <a id="md-04"></a>✅ **Media keys and Now Playing.** The keyboard's media keys and the macOS Now Playing widget stay Chromium's own (Atelier registers no media-key shortcut); they follow the source that started last, which the popover marks as the one media keys control. Playing a source from Atelier gives it that focus.

### Tweaks

- <a id="twk-01"></a>✅ **Tweaks.** Per-site changes to how a page looks and works, without writing an extension. A tweak belongs to one site (its host with `www.` dropped, optionally with every subdomain) and holds hidden elements, a style, custom CSS and, behind an advanced switch, a custom script. Each tweak has an on/off switch that keeps what it holds. Tweaks are stored locally (`tweaks.json`; compatibility: a profile from before the rename has `boosts.json`, which is read once and written to `tweaks.json`, and stays as it was), apply in private windows too, and never run on atelier:// pages or on account sign-in pages (`signInHosts.ts`), even when a tweak covers their domain; a host whose every page is a sign-in page can't have one. The page helper asks for the page's rules before any page script runs, so nothing flashes; CSS goes in with `insertCSS` (outside the page's CSP and out of its scripts' reach) and changes reach open tabs at once.
- <a id="twk-02"></a>✅ **Hide element.** Hide elements picks things on the page to hide. A layer over the page takes the pointer (the page sees no hovers or clicks) and outlines what is under it, frames and shadow hosts included, with its tag and class. Click or Enter hides it; ↑ and ↓ widen and narrow the pick, ← and → step to its siblings; ⌘Z or Ctrl+Z, or Undo, brings back the last one; Esc or Done finishes. A floating bar shows the instructions, a count and Undo and Done, and announces each change to screen readers. Each pick is kept as a selector that survives a reload: stable ids and test hooks first, then hand-written classes (hashed CSS-in-JS and CSS-module classes, state classes and long digit runs are passed over), with positions only where the page has look-alikes. Hiding an element turns the site's tweak on. Hidden elements are listed on the tweak with Show again, and Show all again.
- <a id="twk-03"></a>✅ **Style.** A font (the site's own, sans serif, serif, monospace or rounded, all system faces; code and icon fonts keep theirs), a colour wash over the whole page in one of Atelier's accent hues, an accent for links in text, form controls, the caret and the selection (a hue or any colour), and Focus, which hides sidebars, promos, newsletters, sponsored blocks and share bars but never a box that holds the main content or the page heading.
- <a id="twk-04"></a>✅ **Tweaks in site info.** The site info popover has a Tweaks section: whether the site is tweaked with a summary of what changes, Focus as a quick switch, Hide elements (starts picking and closes the popover) and Customize (opens atelier://tweaks on the site). On sign-in pages it says tweaks don't run there; on atelier:// pages it isn't shown.
- <a id="twk-05"></a>✅ **atelier://tweaks.** Every tweak by host with its summary and switch, one opened for editing at a time (`atelier://tweaks?site=<host>` opens that one, or offers to add it; compatibility: the address from before the rename, atelier://boosts, opens it too). The editor has the hidden elements, the style (font menu, wash and accent swatch groups with arrow-key choice, a colour picker), custom CSS with Save (`@import`, `javascript:` addresses and old script-running properties are left out, with a note saying so), where it runs (on, subdomains), Export and Delete with Undo. A site can be added by address. Allow custom scripts is off by default; turning it on asks first and keeps a warning in view.
- <a id="twk-06"></a>✅ **Scripts, export and import.** With Allow custom scripts on, a tweak can carry JavaScript that runs as each page on the site starts loading, in an isolated world of its own: it sees the page's DOM, never the page's JavaScript or Atelier's. Each tweak's script has its own switch. Export all, or one tweak, writes a JSON file (`atelier-tweaks`, version 1); Import reads one (compatibility: also a file exported before the rename, format `atelier-boosts`), replaces a host's tweak when it already has one, skips sign-in hosts and unsafe selectors, and brings every script in switched off until its new owner turns it on.

### Reader

- <a id="rd-01"></a>✅ **Article detection and extraction.** The page helper (top frame, isolated world, never on account sign-in pages) runs Mozilla Readability's own readerable test on the live page after it is ready, after load and a few seconds later (pages often fill in their article late), and again when the address changes inside the page; it reports only changes. Opening the reader runs Readability on a clone of the document, so the page itself is never touched, and turns the result into a small tree of allowed elements (paragraphs, headings, lists, quotes, code, figures and images, tables, inline emphasis and links), never HTML: scripts, styles, frames, forms, buttons, media and navigation are dropped, links keep only web and mail addresses (in-page links become jumps inside the reader), images only http(s) or small inline sources, lazy images their real source. Main checks the tree again with zod (allowed tags, attributes, addresses and size limits) and accepts answers only from the main frame of the tab it asked.
- <a id="rd-02"></a>✅ **The reader view.** The chrome draws the article over the tab's pane while main keeps the page view hidden (a view cover), so the address, history and page stay as they were. It is a single centred column in Atelier's tokens: the site name, the title, the byline, the reading time (230 words a minute, scripts without spaces counted by characters) and the date, then the article with its images, figures, captions, tables (scrolling on their own when wide) and links. A plain click opens a link in the tab (which leaves the reader), ⌘-click or a middle click in a new tab next to it; jump links scroll inside the reader. Focus moves to the article so Space and the arrows scroll it, each article keeps its place when you switch tabs and back, and Show the original page at the end (or the bar's close button) leaves. A new document in the tab closes the reader; a move inside the page keeps it.
- <a id="rd-03"></a>✅ **Reader button in the address pill.** A book button joins the pill only while the page reads as an article (and while the reader is open, pressed), with a tooltip naming its shortcut. Settings › Appearance › Reader can hide it; the View menu and the shortcut still work.
- <a id="rd-04"></a>✅ **Shortcut and menu.** ⌥⌘R (Ctrl+Alt+R elsewhere) and View › Reader (a checkbox) toggle the reader on the active tab; they are disabled on pages without an article. ⇧⌘R stays Force Reload. While the reader shows, ⌘+, ⌘− and ⌘0 change the reader's text size instead of zooming the hidden page.
- <a id="rd-05"></a>✅ **Text and page settings.** The bar's Text and page panel (Escape or a click outside closes it) sets the typeface (a serif or Atelier's sans), the text size (14 to 32 px in steps), the line width (narrow, medium, wide) and the page colour: Automatic follows Atelier's light or dark mode, Light and Dark pin it, Sepia is the reader's own warm paper with text kept at 4.5:1. The same choices, plus the read-aloud voice and speed and the pill button, are rows in Settings › Appearance › Reader (in the settings search too). They are one choice for the whole app and apply to every open reader at once.
- <a id="rd-06"></a>✅ **Read aloud and Ask the companion.** Read aloud speaks the article with the system's voices (speechSynthesis), one paragraph at a time from the first one in view; the spoken word is marked (CSS Custom Highlight API, so the article isn't changed) and its paragraph tinted, and the column follows along (without animation under reduced motion). A small bar has Pause and Resume (which pick up at the word), Stop, the speed (0.75× to 2×) and the voice (Automatic picks one for the article's language, on-device voices first). Leaving the reader or the tab stops it. Ask {companion} about this article opens the side panel on a new chat with the article's clean text (title, byline, address and body, up to 200,000 characters) as its quoted source, through the same path as the selection chip's Ask ([OV-20](#ov-20)).

### Translate

- <a id="tr-01"></a>✅ **Translate button in the address pill.** On a web page whose language is not one of yours (Settings › Languages, or the system's) a translate glyph joins the pill with one small nod (none under Reduce Motion). It spins while the page is translated, turns solid once translated, and carries a red dot when translating failed; its label says which (Translate this page, Translating this page, Translated from French). A click opens the popover; a second click closes it.
- <a id="tr-02"></a>✅ **Page language and the decision table.** The page helper (top frame, isolated world) reports `<html lang>`, the content-language meta, `og:locale`, the page's own opt-out (translate="no" on `<html>`, `.notranslate`, `<meta name="google" content="notranslate">`) and a sample of its translatable text, at DOMContentLoaded and again two seconds later when the first sample was short. A small on-device detector (writing systems, then each Latin-script language's commonest words, Simplified against Traditional Chinese) weighs in: it overrules the declared language only when it is sure of another (templates often say lang="en"), and on macOS Apple's NaturalLanguage gives a second opinion when it is unsure. Then, in order: web pages only; the page's opt-out; a known language; not one of yours nor the target (Chinese compared by script, regional variants as one); not a site or language you said never to; the always list translates at once (once per page, so Show original sticks); otherwise the offer, unless offers are off.
- <a id="tr-03"></a>✅ **Translate popover.** "This page is in French" (or "Translated from French"), Translate to with a language list (the choice is remembered as your target), Translate or Show original, live progress ("Translating… 120 of 300") and which engine did it, then Always translate French, Never translate French and Never translate this site. A never choice shows the original and hides the button; a new language while translated translates again from the originals. Keyboard and screen readers: Translate takes focus, Esc closes, the status line is announced.
- <a id="tr-04"></a>✅ **Never translate this site.** Stored as the host; it covers that host and the hosts below a listed site (never a bare suffix). Undone from the popover's tick or Settings › Languages.
- <a id="tr-05"></a>✅ **On-device translation first.** native/translate (atelier-translate, Swift, built by scripts/build-translate-helper.mjs, shipped through electron-builder's mac extraResources) runs Apple's Translation framework with a TranslationSession per language pair (macOS 26) and answers JSON lines that main checks with zod. Nothing leaves the Mac. A pair whose languages are not downloaded says so, with Open Language & Region (System Settings › General › Language & Region › Translation Languages); before macOS 26, or off macOS, translation on the computer says it is unavailable. The helper starts on first use and stops after five quiet minutes.
- <a id="tr-06"></a>✅ **Translate with your companion.** Off by default. When on, the companion's engine (your API key, or another engine, through QuickModel, Haiku at low effort) translates when this Mac can't, and takes over mid-page if Apple's languages go away. The prompt asks for one translation per fragment in order, with page text treated as content, never as instructions. Its description says the page's text is sent to the model.
- <a id="tr-07"></a>✅ **Translation in place.** Text nodes are changed where they are, so markup, links, styles and listeners stay; the document title, title, alt, placeholder and aria-label are translated too. Code, pre, kbd, samp, var, inputs, textareas, selects, SVG, math, frames, media, contenteditable regions, hidden inputs, and anything under translate="no" or .notranslate (unless translate="yes" says otherwise) are left alone and never sent. Open shadow roots are included. Leading and trailing white space stays put.
- <a id="tr-08"></a>✅ **Batches.** Texts go out in document order, each unique text once, in batches of at most 64 texts and 4000 characters; a text longer than a request allows is cut at sentence ends. Each batch is applied as it returns, so the top of the page changes first. Main refuses batches from a session that a navigation, a restore or a new target ended.
- <a id="tr-09"></a>✅ **Show original restores exactly.** Every change is recorded; Show original puts every original back, except text the page itself replaced since (that stays as the page wrote it), and stops any batch still out. A failure partway restores the page and reports the reason.
- <a id="tr-10"></a>✅ **Dynamic pages.** While translated, a MutationObserver gathers what the page adds or rewrites (text, nodes, translated attributes) for 250 ms and translates it in the same session, judging new nodes by their ancestors; the translator's writes are recognised and skipped. Moves inside a single-page app keep the translation; a new document starts over.
- <a id="tr-11"></a>✅ **Popover surface.** The popover is an overlay surface (translate-popover) that follows the tab's state while open, closes on a tab switch, Esc or a click outside, and reads in light and dark through the tokens.
- <a id="tr-13"></a>✅ **Page menu.** A right-click on the page itself (not a link, image, field or selection) offers Translate to <your target language> on any page whose language is known and not the target, even on a site or language you said never to offer (the way back to translating it once), and Show original while translated.
- <a id="tr-12"></a>✅ **Translation settings.** Settings › Languages › Translation: Offer to translate pages, Translate into (your first language, or a chosen one), Translate with your companion, Translating on this Mac (with Open Language & Region), and the Always translate, Never translate and Never translate these sites lists, each entry removable. Stored per profile; every row is in settings search.

### Bookmarks

- <a id="sh-47"></a>✅ **Bookmarks bar.** The bar sits under the toolbar in the content column. It shows always, only on the new tab page, or never, and ⇧⌘B toggles between always and never. Folders open nested menus ([SH-48](#sh-48)). ⌘-click or middle-click opens a link in a background tab. Items rename inline, drag to reorder, and drop into a folder when held over its middle third, and an overflow button holds whatever doesn't fit. Context menus cover: open in a new tab, window or private window; open all (also as a new group); copy link, rename, edit and delete (with confirmation); add the current page, add a folder, open the manager, and visibility.
- <a id="sh-48"></a>✅ **Bookmark folder menus.** Clicking a folder opens a list up to about 400 px wide, clipped to the window. Subfolders open further panels to the side, and closing one level closes the deeper ones. A click opens a bookmark in the current tab, and a middle-click opens it in the background. Items drag to reorder or move between folders, with a visible drop target. There is an empty-folder state, and panels close on an outside click, a space switch, or when the folder is deleted. This needs folders in the bookmark store first.
- <a id="sh-49"></a>✅ **Bookmark editor.** The star and ⌘D open a popover anchored to the star, with name, URL and folder fields; a new folder can be created right there. On a saved page they edit the existing bookmark. Remove switches the popover to a removed state with Undo. Enter saves, Esc closes, and save errors show inline.

There is no sign-out item.
- <a id="sh-51"></a>✅ **File menu.** New tab; new tab in the current group (⌥⌘T); new window (⌘N, with a per-profile submenu once profiles exist); new private window (⇧⌘N); reopen closed tab (⇧⌘T); open location (⌘L); close window (⇧⌘W, closing a focused popup first); close tab (⌘W); close all tabs; save page as complete HTML (disabled on atelier:// pages); share through the macOS share sheet; and print (⌘P).
- <a id="sh-52"></a>✅ **Edit menu.** The standard undo, redo, cut, copy, paste, paste and match style (⇧⌘V), delete and select all. It adds copy page URL (⇧⌘C) and copy page as a Markdown link (⌥⇧⌘C), each confirmed by a toast, the macOS speech submenu, and a find submenu with find (⌘F), next (⌘G) and previous (⇧⌘G).
- <a id="sh-53"></a>✅ **View menu.** Appearance radios (system, light, dark), the layout switch and show sidebar (⌘S); toggle the companion panel (⌘J) and new chat beside the page (⇧⌘E); bookmarks bar modes plus ⇧⌘B; stop (⌘.), reload (⌘R) and force reload (⇧⌘R); zoom; full screen; and a developer submenu with view source (⌥⌘U), developer tools (⌥⌘I), inspect and JavaScript console (⌥⌘J). Developer items act on the focused surface and beep when there is none.

It holds: a local profile block (profile, name initial, API key status, switch, manage and import); tabs (new tab, new window, private window, search tabs and chats); bookmarks (bookmark this tab, bookmark all with a summary toast, bar visibility, manager); recent history (the last eight, with an empty state); downloads, passwords and extensions; an appearance flyout with compact theme, accent and layout controls that write the same settings as the Appearance page; save and share (copy page as Markdown, screenshot the tab, save as PDF, save page); more tools (ad blocking, print, find, the zoom row, rename window, search engine, clear cache and cookies, developer tools); an update or default-browser banner when relevant; help (what's new, send feedback, report a problem, check for updates, about); and settings. Items show the native menu's shortcuts, submenus open on hover with a forgiving pointer path, and Esc closes the innermost level first. There are no account or plan sections.
- <a id="sh-55"></a>✅ **Tabs menu.** New tab in the current group; next and previous tab (⌥⌘→/⌥⌘←); duplicate; mute or unmute site; close tab; search tabs and chats (⇧⌘A); and a checkable list of open tabs. The list holds up to about 48 of the most recently shown tabs in list order, always includes the active tab and notes how many were left out. Hidden items carry ⌘1–9.
- <a id="sh-56"></a>✅ **Bookmarks menu.** Bookmark this page (⌘D, opens the editor); bookmark all tabs (⇧⌘D, skipping duplicates and saved pages); manage bookmarks (⌥⌘B); recent bookmarks; and folder submenus mirroring the bar and other bookmarks, with favicons, an open-all item per folder and a note when entries were left out.
- <a id="sh-57"></a>✅ **History menu.** Back (⌘[) and forward (⌘]) with live enabled states; home (the new tab page); recently closed (10); recently visited (15, with favicons); recent chats (10) with a show-all-chats item; and show history (⌘Y). It refreshes shortly after each navigation. Searching chats happens in the command bar, because native menus can't hold a search field.
- <a id="sh-58"></a>✅ **Window, Extensions and Help menus.** Window has minimize (⌘M), zoom, minimize all (⌥⌘M), bring all to front, downloads (⇧⌘J) and a checkable list of open windows. Extensions lists installed extensions with icons (a click runs the extension's action), plus add, manage and pin. Help has help topics ([ON-17](#on-17)), send feedback as an email draft, copy diagnostics (app, OS, Electron and Chromium versions, with a toast) and the keyboard shortcuts sheet.
- <a id="sh-59"></a>✅ **Live menu rebuild.** The native menu is rebuilt whenever its state changes (enabled items, checkmarks, recent lists, tab and window lists). A rebuild waits while a menu is open. The top-level structure and the accelerator map are shared with the chrome, so the main menu and tooltips show the same shortcuts. On Windows and Linux, an in-window button can pop up any top-level submenu.

### Windows and profiles

- <a id="sh-61"></a>✅ **Window management.** Several windows. A new window uses the current profile and opens 24 px offset from the focused one. Private windows use an in-memory session partition. A window can be renamed; otherwise its title follows the active tab. All windows, their bounds and display mode are restored on launch. On macOS the title bar is hidden with repositioned window controls, and the window background follows the theme. Minimise, minimise all and full screen work.
- <a id="sh-62"></a>✅ **Popup origin strip.** Popup windows that pages open (sign-in, payment) get a read-only strip at the top with the host, a secure or not-secure marker and a loading state, updated as the popup navigates. When the popup closes, focus returns to the tab that opened it.
- <a id="sh-63"></a>✅ **Navigation rail on atelier:// pages (horizontal layout).** In the horizontal layout, atelier:// pages get a collapsible left rail with new chat, the destinations with live badges, recent chats and the profile menu, toggled with ⌘S. It resizes by drag or with ←/→ in 8 px steps, and a one-time hint points it out.
- <a id="sh-64"></a>✅ **Profiles.** Profiles separate your browsing. Each has its own session, colour, windows, settings (theme, layout, sidebar order and visibility, zoom) and pinned tabs. You switch them from the main menu, the app menu and the Dock menu, and you can import one from another browser. Companions, the Library, and saved passwords, addresses and cards stay shared across profiles. Spaces inside a profile (the Space row) belong to workspace projects.
- <a id="sh-65"></a>✅ **Extension buttons.** Pinned extensions show as toolbar buttons with an icon and a badge. The extensions button lists all of them: a click runs the extension's action, and each has pin/unpin, manage, remove (after a confirmation) and report a problem. It links to getting extensions when the list is empty. An unpinned extension appears temporarily while its popup is open, installs confirm with a toast, and manifest shortcuts register unless they clash with built-in ones.

### Shortcuts

- <a id="sh-66"></a>✅ **Shortcut routing.** One shortcut table in main covers every surface, and each entry says whether it overrides the page. ⌘T, ⌘W, ⌘L, ⌘J, ⌃Tab, ⌃⇧Tab and the zoom keys always go to the browser. Other shortcuts yield when the page handled the key, and ⌘←/⌘→ are left to text fields. Shortcuts that would act on an agent-controlled page (reload, back, close) wait until you take over or pause the agent.
- <a id="sh-67"></a>✅ **Keyboard shortcuts sheet.** ⌘/ and Help open a sheet listing every shortcut from the shared table, grouped by surface and formatted for the platform.

## Chat

### Foundations

- <a id="ch-01"></a>✅ **One agent session per chat.** Main runs one session per chat, and agent events are keyed by chat id. Chat pages, per-chat badges, parallel chats and companion ownership all depend on this.
- <a id="ch-02"></a>✅ **Chat record fields.** Each chat summary gains companion, unread, pinned, archived and needs-input fields, plus the routine it belongs to (already stored). A chat's setup (companion, system prompt, tools, model) is fixed when it starts. Switching companion, connecting a connector or changing model mid-chat continues in a new chat.

### Chat page and panel

- <a id="ch-03"></a>✅ **Side panel.** ⌘J toggles the companion chat beside the active page, and ⇧⌘E opens it on a fresh chat. The panel sits behind a draggable seam, the same component split view uses, with a minimum and maximum width. Arrow keys move a focused seam, and the width is saved. The panel docks on the right by default, or on the left. Its header is the same floating chip as the chat page (the companion's face, the title and a status word) with switch, expand, ⋯ and hide. Expand hands the chat over: the panel closes and the chat opens as a page with the page it sat beside shown next to it, keeping the draft, the scroll position and the words already revealed; a control on the chat page moves it back into the panel ([DS-64](design-spec.md#ds-64), [DS-65](design-spec.md#ds-65)). Once there are several windows it can pop out into its own window. Only one surface drives a running chat at a time; the others mirror it.
- <a id="ch-select"></a>✅ **Selectable chat text.** Your messages and the companion's answers (Markdown, code and tables included) can be selected with the mouse and copied; the rest of the window stays unselectable.
- <a id="ch-04"></a>✅ **Chat page.** atelier://chat/&lt;id&gt; shows the conversation in one centred 640 px column that the replies, your messages and the composer share ([DS-50](design-spec.md#ds-50)), with the composer at the bottom (or at 40% of the height while the chat is empty, [DS-107](design-spec.md#ds-107)). Pages the chat opened can show beside it, expanded to full width or hidden.
- <a id="ch-05"></a>✅ **Chat header and actions.** A header inside the content card shows the title (click to rename), the owning companion's avatar, a routine pill for routine chats ([SK-11](#sk-11)), a button for the tabs this chat used ([CH-33](#ch-33)) and a ⋯ menu. The title is named from the first message, with a neutral placeholder until then. The menu has new chat, rename, duplicate, open in a new tab, export and delete. Delete asks for confirmation, saying it can't be undone, or offers Undo on a toast. Duplicate copies the saved history and event log and confirms with a toast.
- <a id="ch-06"></a>✅ **Composer hint.** The hint follows the composer's state, with one for each of: an empty chat, a follow-up, a running chat (the message joins the queue), editing a queued message, an attached meeting, and no API key. Hints use the companion's name.
- <a id="ch-07"></a>✅ **Companion, model and effort chip.** A chip beside the composer shows the chat's companion. Its menu picks another companion (with search) for a new chat, and sets model and effort for this chat before the first message. Switching companion mid-chat offers to continue in a new chat. If the companion was deleted or hidden, the chat falls back to the default one with a notice. Models without effort control show a short note.
- <a id="ch-08"></a>✅ **/ skills and # search.** Typing / lists skills, with the current companion's own first and shared ones after. Arrow keys move, and Tab or Enter inserts. Typing # searches records inside connectors that support search, and the list hides when nothing matches.
- <a id="ch-09"></a>✅ **Copy and edit your own messages.** Hovering a user message shows Copy and Edit, and ↑ in an empty composer edits the latest message. Edit opens an inline editor for the text and attachments. Saving cuts the chat back to that point and sends again, after a confirmation when later replies will be discarded. The cut is valid because the history before it doesn't change.
- <a id="ch-10"></a>✅ **Reply footer.** Each reply has copy as Markdown; helpful and not-helpful ratings stored locally on the message; retry; and a details popover with the time, model and token usage. A small marker shows when the turn saved or changed memory, linking to the files involved.
- <a id="ch-11"></a>✅ **Rating note.** A rating opens an optional inline note, typed or dictated, with Save and Skip. It is stored with the message and never sent to the model.
- <a id="ch-12"></a>✅ **Keep the reading position.** When you have scrolled up, new output doesn't move the view. A jump-to-newest button with a new-content dot appears instead.
- <a id="ch-13"></a>✅ **Paging and message links.** Long chats render the newest messages first and load older ones as you scroll up. Links can point at a message (atelier://chat/&lt;id&gt;#&lt;message&gt;); if it no longer exists, a notice offers a jump to the newest.
- <a id="ch-14"></a>✅ **Step limit and continue.** When a run reaches the step limit (60 steps), a notice card offers Continue, which resumes the same chat; typing a new message changes direction instead. The card also links to Settings › Model and key › No step limit, which lets runs go on until they finish or you press Stop; it applies from a run's next step, on every engine and to routines. A run you stopped is marked as stopped inline, and the companion goes back to idle.
- <a id="ch-15"></a>✅ **Message queue.** Messages sent while the companion works join a visible queue above the composer and go out in order. Each can be edited in place (save or cancel), removed, or sent now, which interrupts the run. A failed send can be retried. If an item leaves the queue while it's being edited, you can discard the edit or send it as a new message. Queued routine runs aimed at this chat are listed too.
- <a id="ch-16"></a>✅ **Interrupt and redirect.** ⌘↩ during a run stops the turn at a safe point and shows an interrupting state. Every tool call already made gets a result, so the history stays valid, and then the new message is appended and the run continues.
- <a id="ch-17"></a>✅ **Stop.** While the companion works, Send becomes Stop, and Esc in the composer also stops. Long-running steps, such as a server tool, show their own running state and are cancelled with the run.
- <a id="ch-18"></a>✅ **Per-chat permission mode.** A composer toggle sets this chat to ask before consequential actions (the default) or to act without asking, shown as a badge while it's on. Guarded password, one-time-code and payment fields stay blocked either way. New chats start from the global setting.
- <a id="ch-19"></a>✅ **Grouped work trace.** Consecutive tool steps fold into one collapsible group with a plain summary (for example, read three pages and searched twice) and connector icons. Expanding shows each step's input, a result summary and any error. A live timer shows how long the current step has run. Reasoning can be shown or hidden per reply, and the choice is remembered.
- <a id="ch-20"></a>✅ **Live activity status.** The header status and the line above the composer describe the current step in plain words (reading a page, searching the web, checking memory, using a connector, waiting for approval), updated from tool events.
- <a id="ch-21"></a>✅ **Add-context menu.** A + button attaches files, an open tab's content, a skill, a meeting transcript or a local folder to work in. Each submenu has its own search and empty state. A switch controls whether activity memory is included.
- <a id="ch-22"></a>✅ **Attachment chips.** Attached items show as removable chips above the composer: files, images, tabs, selected text with its source link, meetings, and answers to agent questions. Each shows preparing, ready or failed (with retry), and Send waits until all are ready. When the files-and-documents ability is on, a small badge says server-side code execution is enabled.
- <a id="ch-23"></a>✅ **Drop files on the chat.** Dragging files over the chat page, the panel or the composer shows a drop overlay, and dropping attaches them. Unsupported or oversized files are rejected with an inline reason.
- <a id="ch-24"></a>✅ **Long paste becomes a chip.** Pasting over about 1,500 characters or 30 lines collapses the text into a chip showing its line count. Clicking it opens a preview where it can be edited or put back into the composer, and it is sent as a text attachment.
- <a id="ch-25"></a>✅ **@ mentions.** Typing @ opens a list with filters for open tabs, past chats, companions and connectors. A tab or chat becomes a token whose content is attached at send time. A companion offers to start the chat with it, and a connector tells the agent to use it. The list has keyboard navigation and an empty state.
- <a id="ch-26"></a>✅ **Compaction marker.** When a long chat's context is compacted, a divider appears with an expandable summary of what triggered it and roughly how much it replaced. A status shows while compaction runs.
- <a id="ch-27"></a>✅ **Rich cards in replies.** Cards for: suggested follow-ups that send in one click; memory saved or forgotten; tabs the agent opened, with Switch to tab; files it produced; and artifact previews. Connector drafts appear as approval cards ([CH-40](#ch-40)). A notice marks a result as partial when the run ended early.
- <a id="ch-28"></a>✅ **Chat files browser.** A modal shows everything a chat has gathered as folders: tabs it read, attachments, messages, tool results, context and generated files. It has back navigation, sizes and character counts, and previews for images (including SVG), text, Markdown, code, HTML and spreadsheets, with placeholders for binary, empty or unknown files. Other files get Reveal in Finder. Esc or close dismisses it, and chats with no files get an empty state.
- <a id="ch-29"></a>✅ **Tips while the companion works.** When a run lasts more than a few seconds, one short tip appears under the live status and rotates about every ten seconds. Each can be dismissed, tips can be turned off, and they never cover approvals or errors.
- <a id="ch-30"></a>✅ **Private chat.** A toggle on the new-tab composer and the chat page starts a chat that isn't saved, with the memory tool off and an indicator in the header. Closing it discards it, with a confirmation if it has content. Routines can't target it.
- <a id="ch-31"></a>✅ **Read-only imported conversations.** Conversations imported from another assistant's export open as read-only transcripts. A banner says where they came from and offers to carry on in a fresh chat, seeded with a short summary or the transcript as context, because imported messages can't join an API history. Exported Atelier chats import the same way.
- <a id="ch-32"></a>✅ **Delegated sub-tasks.** If the agent hands work to helper agents, each helper runs in a child chat linked to its parent. The parent shows a compact delegation card, and the child's header links back. A child opens as a full chat or docks in the details panel with its own composer. Its status is working, done, needs attention, needs input, stopped, or interrupted by a restart, and a stopped or interrupted sub-task can be continued.
- <a id="ch-33"></a>✅ **Tabs used by this chat.** A header popover lists the tabs the agent opened or acted on in this chat, each with Switch to tab and Close, plus close all. In side-by-side mode, a small strip of those tabs switches the page shown next to the chat.
- <a id="ch-34"></a>✅ **Pages in this chat menu.** A toolbar control (a stack of up to three favicons plus a count) lists the pages the current chat opened or holds as context, with thumbnails and one selected at a time. A page the agent is driving glows in the companion's accent. Choosing a page brings it forward, and each can be closed or removed from the chat's context, except while the agent controls it. Up/Down move, Delete removes the focused page and Esc closes.
- <a id="ch-35"></a>✅ **Chat details panel.** A collapsible side panel on the chat page shows the agent's plan or checklist, files produced, web sources cited, skills used, connectors active, delegated sub-tasks and the chat's token usage.
- <a id="ch-36"></a>✅ **Export dialog.** One dialog for chats, skills, meeting transcripts and generated documents. It copies as text, saves as Markdown, HTML or PDF, prints, reveals the saved file, and opens a mail draft with the text inline. This is the local stand-in for share links.
- <a id="ch-37"></a>✅ **Find in a chat.** ⌘F on a chat page, or with the panel focused, finds across the chat's messages, including older ones not loaded yet, with a count, next and previous, and highlighting. On a website, ⌘F still finds in the page.

### Approvals and requests

- <a id="ch-38"></a>✅ **Request tray.** Everything waiting on you (approvals, questions, sign-in or CAPTCHA hand-offs) stacks in one tray pinned above the composer, so it stays visible while you scroll. With several items there is a counter with previous and next, plus allow-all and dismiss. Hand-offs have a Done button that resumes the agent. Each item grows up out of the composer and collapses back the same way when answered; there is no looping pulse, and attention comes from that entrance, the mark on the companion's face and the notification ([DS-62](design-spec.md#ds-62)).
- <a id="ch-39"></a>✅ **Approval scope and per-site rules.** An approval can apply once, for the rest of the chat, or always for this site and kind of action. The broader scopes explain what they allow and need a second confirmation. Payments, passwords and account-security changes always ask. Settings › Agent permissions lists saved rules per site (allow, ask, never), and per tool for locally run connectors, each removable.
- <a id="ch-40"></a>✅ **Editable connector approvals.** Before a locally run connector action, its inputs show as a form built from the tool's input schema: recipients as validated chips, subject and body, and dates and times with a time zone. A raw JSON view and a summary of your edits are available. The confirm button is named after the action, and declining can send a short message back as the tool result. Remote connectors run server-side, so this applies only to local servers.
- <a id="ch-41"></a>✅ **Connect a connector from the chat.** When a request needs a connector that isn't set up, an inline card offers to connect it: sign-in where an official server exists, otherwise a token. It shows connecting and failed states, and the request then continues in a new chat, because a chat's tools are fixed when it starts.
- <a id="ch-42"></a>✅ **Countdown on auto-approved actions.** When a saved rule approves a consequential action, an eight-second countdown bar says what's about to happen, with Stop and run-now.
- <a id="ch-43"></a>✅ **Site, folder and table prompts.** With per-site access set to ask, the first action on a new site asks: allow this time, for this chat, always on this site, or block. Choosing a local folder asks for read-only or read-and-edit access, and whether it applies to all chats. Writes to local tables show the statement and its scope, with a warning for destructive changes.
- <a id="ch-44"></a>✅ **Question cards.** The agent can ask structured questions through a client-side tool. Each has suggested answers and a free-text answer, with previous and next, skip one, skip all, and a submit button that counts the answered questions. A question can link to a page to look at first, and the answers return as the tool result.

### Chat lists

- <a id="ch-45"></a>✅ **All chats page.** atelier://chats groups chats by today, yesterday, the previous 7 days, the previous 30 days and older, with pinned chats on top. It searches titles and content, sorts by best match, newest or oldest, and filters by companion, routine runs and status (unread, needs input, archived). It has clear-filters and incremental loading, and each row shows its companion's avatar.
- <a id="ch-46"></a>✅ **Chat row actions.** Each row's menu has open in a new tab, inline rename (Enter saves, Esc cancels), duplicate, pin, archive or restore, export and delete. Delete asks first or offers Undo.
- <a id="ch-47"></a>✅ **Chat context menu.** Right-clicking a chat in the sidebar or the list offers: open, open in a new tab, pin or unpin, mark read or unread, rename, duplicate (with a toast, and a warning if some attachments couldn't be copied), archive or restore, export, and delete with confirmation. A section menu marks every chat read.
- <a id="ch-48"></a>✅ **Bulk chat actions.** A selection mode adds checkboxes and a bar with select all, clear and done. Bulk actions are delete (confirmed, permanent), archive, mark read or unread, and export.
- <a id="ch-49"></a>✅ **Chat preview pane.** Selecting a row opens a side preview with a reply box, mark read, a running indicator and open in full.
- <a id="ch-50"></a>✅ **Chat list popover.** A popover from the panel header lists recent chats with search, filters (unread, needs input, routine runs), mark all read and a link to All chats. A routine inbox lists unread routine results and runs that need input, with open all. It is keyboard-driven, with states for a load error, no matches and no chats yet.

## Companions

- <a id="co-01"></a>✅ **Ownership and migration.** Chats, skills, routines, files and memory are owned by a companion or shared with all. On first launch after the change, a migration hands existing global items to the first companion, or marks them shared.
- <a id="co-02"></a>✅ **Companion profile card.** A large card, opened from the companion's avatar, with tabs for General, Skills, Routines, Files, Memory and Models; arrow keys move between tabs. Each tab can be linked to directly (atelier://companion/&lt;id&gt;/&lt;section&gt;), down to a single skill, file or routine. It covers only the content area (the page there is washed and blurred; the sidebar and toolbar stay sharp and usable), or fills the chat column it was opened from, fades in and out, and can be resized from its left edge. An atelier://companion tab draws the same card as a page filling the content area, with no border, radius or backdrop, and closing it closes the tab ([DS-121](design-spec.md#ds-121)). The hero figure keeps one size on wide cards and in the tab ([DS-40](design-spec.md#ds-40)). The header is one row: a switcher pill (face, name, chevron) whose menu lists the companions, then New companion… and Add from file…; and only More and Close on the right. One floating pill under the header shows the save status (saving, saved, or couldn't save with retry) for every field; the name is edited in the hero ([DS-33](design-spec.md#ds-33), [DS-34](design-spec.md#ds-34), [DS-42](design-spec.md#ds-42)).
- <a id="co-03"></a>✅ **Card actions.** In the hero: Export… (a `.ateliercompanion` file plus a share image) as the companion-coloured primary pill, and Customize look, which edits the look in place with undo and redo. The ⋯ menu holds the rarer actions: use for new chats; the Dock icon (macOS); duplicate (with progress); hide or unhide, where hidden companions leave the switcher and new-tab picker but keep their chats; reset; and delete ([DS-35](design-spec.md#ds-35), [DS-41](design-spec.md#ds-41), [DS-42](design-spec.md#ds-42)). Delete asks for confirmation and explains what happens to the companion's chats.
- <a id="co-04"></a>✅ **Keep at least one companion.** Delete is disabled, with an explanation, when only one visible companion remains. Deleting the active companion switches to another, and a deleted companion's chats stay readable with a neutral avatar.
- <a id="co-05"></a>✅ **Standing instructions.** The General tab shows the instructions the companion follows in every new chat as plain prose, edited in place, under a muted label whose info tooltip carries the explanation. An empty text shows the default prompt; it autosaves through the card's save pill, and a counter appears only near the length limit. The personality preset is a small ghost select at the end of that label row, and the summary above keeps exactly two rows, skills and routines ([DS-45](design-spec.md#ds-45), [DS-46](design-spec.md#ds-46)). Edits apply only to new chats.
- <a id="co-06"></a>✅ **Skills tab.** The companion's own skills with search, then a collapsible group of shared and built-in skills. Each shows its description, when it was last used, a Use button that starts a chat with it, and a menu to reveal in Finder, export or delete. A create menu offers: build it with the companion in a chat, write it from a blank skill, or import a skill file.
- <a id="co-07"></a>✅ **Routines tab.** The routines that run as this companion, with schedule and next run. Opening one shows its page in a tab, after a confirmation before leaving the card.
- <a id="co-08"></a>✅ **Files tab.** Files in the companion's own folder, with a filter, sorting by name or last modified, breadcrumbs for subfolders, and open, reveal in Finder and delete for each. Files can be dropped in (folders can't), unsupported files are view-only, and the agent can read these files in this companion's chats.
- <a id="co-09"></a>✅ **Memory tab.** The companion's own memory folder. Notes are grouped by date, can be filtered by author (the agent or you), and can be opened, edited and deleted. The tab links to the nightly tidy, with its last and next run and an off switch.
- <a id="co-10"></a>✅ **Models tab.** The default model and effort for this companion's new chats. The global default is overridden by the companion's default, which is overridden by a per-chat choice made before the first message, and existing chats keep their snapshot.
- <a id="co-11"></a>✅ **Appearance editor.** Body, head, hair, ears, hat, glasses, earwear, prop and face layers, the four colours, curated palettes and Shuffle, plus undo and redo for every change. Shuffle can be biased towards a named style (for example soft, bright, bold). Fine-tuning a part's size, position and rotation is optional and must respect the compatibility rules. There is one look editor: the card's, a ring of category bubbles around the figure, each opening its options beside it. Settings › Companions › Customize look… (for any companion) and the old atelier://settings/companion open the card at atelier://companion/&lt;id&gt;/general/look with it on; Done drops /look from the address.
- <a id="co-12"></a>✅ **Create a companion.** A new-companion action in the switcher, the new-tab picker, the card and Settings › Companions opens a sheet with a name, a live preview that starts shuffled or from a preset, and Customize look, which adds the companion and opens its card with the look editor ([CO-11](#co-11)) instead of the welcome. Creating adds the companion, with its own memory folder, skills and chats, and makes it active. Names are trimmed and length-limited, a duplicate name gets a suffix, and cancelling adds nothing.
- <a id="co-13"></a>✅ **New-tab companion picker.** *Superseded in part by [DS-75](design-spec.md#ds-75) and [DS-77](design-spec.md#ds-77).* The one who takes the next chat stands live above the composer, and a switcher pill at the top centre shows its face and name, opens a companion menu, and adds a companion. By default the new tab is also the companion floor ("the Lounge"): every other visible companion stands on it, and choosing another (a click, ←/→ while the composer is empty, the switcher, or dragging one onto the composer) flies it up and bumps the previous one back to the floor. With "Companions on New Tab" off (a remembered round toggle at the top right), the switcher lists every companion and the selected one offers help in a speech bubble. ←/→ also reach an add entry at the end, the choice is remembered, and Tab keeps moving focus.
- <a id="co-14"></a>✅ **Import a companion file.** Opening a `.ateliercompanion` file (double-click, a drop on the window, or Settings › Companions) shows a review sheet: the look, name, any creator note, instructions, and included skills and routines, with add and cancel. Everything the companion tells the assistant is there to read, collapsed: each skill's instructions, steps and supporting text files (a file too long to show gives its size), and each routine's prompt. Adding creates a new companion and never overwrites one. Invalid files and files from a newer version show a clear error, and name clashes get a suffix. Memory is included only if the exporter chose to include it.
- <a id="co-15"></a>✅ **Built-in presets.** A gallery of Atelier's preset companions, in the switcher and the new-companion sheet, shows each preset's name, tagline and look. Adding one creates a new companion from it instead of overwriting the current one.
- <a id="co-16"></a>✅ **Off-screen snapshots.** A hidden renderer draws the companion to images (avatar, full body, face portrait, blink frame, Dock icon), retrying on timeout and caching per look. The card's share image comes from the same path.
- <a id="co-18"></a>✅ **Face avatars at small sizes: a floating head.** Wherever the companion is drawn small (under about 80 px: sidebar chat rows, tab agent badges, the composer chip, the chat header, All chats rows, Settings › Companions, the panel header, the card's switcher and menus), it shows only the floating head: the head with its hair, ears and hat, on a transparent background, with no circle, disc, ring, border or background shape around it, so it never looks like a profile picture. It is centred on the face, fills its box without clipping a hat or ear, keeps a crisp outline at every size and retina resolution, and may carry a very soft contact shadow so it reads on any surface in light and dark mode. Where the avatar stands for a chat, its expression follows that chat's state: idle, working, needs approval, done or error. The full body appears only at large sizes (about 100 px and up). The person's own avatar in the sidebar footer is a profile picture and keeps its round frame. Status is never drawn on or over the head: a chat's state shows as a separate small mark beside it, side by side ([DS-67](design-spec.md#ds-67)), and the head is never masked, notched or cut into a circle. *Gap (user requests, 2026-10-28):* the small avatars still sit in a round, clipped disc with state marks layered on the face; remove the disc and clipping everywhere, draw the free floating head, and move every state mark beside it.
- <a id="co-19"></a>✅ **Always alive and responsive.** Wherever the companion is shown at a large size, it is the live character, never a still image. It breathes and blinks, looks towards the pointer, reacts when clicked, and follows the mood of the chat it belongs to: listening while you type, thinking and working while the agent runs, asking when approval is needed, and happy when a task is done. Reduce Motion keeps it calm. It fills the space it is given and re-frames when that space changes, switching smoothly between the face crop and the full body at the size threshold without ever clipping a hat, ear or prop. One presence store drives every view of a companion or chat ([DS-68](design-spec.md#ds-68)); a pat on the head, long idle (looking around, then a nap) and a celebration when a companion is added are shared by all its views ([DS-70](design-spec.md#ds-70)). To stay within the GPU's context limit, live figures are used from about 96 px up with a cap on how many run at once; the rest, and any figure off-screen, show a breathing still with blinks and swap back without a flash ([DS-71](design-spec.md#ds-71)).
- <a id="co-20"></a>✅ **Waiting in a new chat.** An empty chat, both as a page and in the side panel, shows the full-body live companion standing in the chat, waiting, instead of a profile picture. It greets once when the chat opens and then idles. While you type it turns to listen, holding while the composer has text, even if the companion is working in another chat, and when you send the first message it moves into thinking as the conversation starts. It is sized to the room available (up to about 200 px on the chat page and 140 px in the panel), with the greeting below it. The empty chat uses the start composition ([DS-107](design-spec.md#ds-107)): the composer's top sits at 40% of the height with the companion above it and the ideas below it, and the first send glides the composer down to its place at the bottom ([DS-73](design-spec.md#ds-73)).
- <a id="co-17"></a>✅ **Preset detail.** A preset's detail sheet shows its look, tagline, a summary of its personality (full text behind a toggle), and its starter skills and routines. Adding it shows a short preparing state, then the button changes to start a chat. A preset already added offers to open that companion. If an update changed the preset, you are offered a review of the differences, and your own edits are never overwritten.

## Skills, routines and apps

### Skills

- <a id="sk-01"></a>✅ **Skills page.** atelier://skills (the sidebar's Skills row) groups your skills, companion skills and built-in skills. It has search, sorting (recently used, recently updated, name) and filters for source, owning companion and update date. Each card shows the description and a Run button.
- <a id="sk-02"></a>✅ **Create, import and delete skills.** A skill can be drafted by the companion in a chat and saved after you confirm, written by hand, or imported from a Markdown file; a skill the companion drafts is its own (the other companions don't get it), and drafting under the name of one it already has changes that skill (a Skill update card with Save changes). The companion's own skills are listed in its prompt, and read_skill lets it read any skill it can use before following or changing it; empty or invalid files are rejected with a reason. Save as skill on a chat does the same. Delete asks for confirmation, and built-in skills can't be deleted.
- <a id="sk-03"></a>✅ **Skill editor and folder format.** Each skill is a folder with a main Markdown file whose frontmatter (name and description) is validated, plus optional supporting files that can be browsed, edited and dropped in. The editor has title, description and instructions, Save, a prompt before discarding changes, export, use, reveal in Finder and a marker on skills shared by all companions. Built-in skills open read-only.
- <a id="sk-04"></a>✅ **Skills in a chat.** Skills are invoked with / or from the add-context menu. The sent message shows a skill chip that opens the skill, instead of the raw command text, and built-in skills carry a badge.

### Routines

- <a id="sk-05"></a>✅ **Routines page.** atelier://routines has two views: routines and their past runs. It filters by status (active or paused), companion and schedule type, searches, and sorts by name or next run. Each row has run now, pause or resume, edit, delete with confirmation and the last run. A routine whose companion was deleted prompts you to pick another. Finished one-off tasks sit in a past group, and suggested routines can be dismissed.
- <a id="sk-06"></a>✅ **Set up a routine in chat.** The agent can propose a routine through a client-side tool. The proposal is a card with save and edit, and the agent can list routines as cards.
- <a id="sk-07"></a>✅ **Routine editor.** Reads as one sentence: when this happens, this companion does that. Fields: name, companion, instructions (typed or dictated) or a skill, timing, destination (a new chat for each run, or appending to one chat) and run once. Each missing field gets its own message. If the routine changed elsewhere while you edit, the editor offers to load the new version.
- <a id="sk-08"></a>✅ **Schedule types.** Daily (every day, weekdays, weekends or chosen days, at a preset or custom time, shown in 12- or 24-hour format by locale). Interval (every 30 minutes up to 24 hours, optionally only between set hours and on set days). Advanced (a five-field cron expression with validation and a preview of the next runs). Once (a future date and time). A searchable time-zone picker is included. Triggers from connector events wait, because they need polling or a backend.
- <a id="sk-09"></a>✅ **Routine detail and run history.** Each routine has a page with its state, created and updated dates, next run, instructions, run now, and pause or resume. Its run history links each run to its chat with a status, can mark all read, and loads more on demand.
- <a id="sk-10"></a>✅ **One-off tasks.** A task can be scheduled once for a date and time, then edited, run now or deleted. The delete warning says it won't run and that past result chats are kept. After it runs, it moves to the past group.
- <a id="sk-11"></a>✅ **Routine pill.** A routine chat's header shows a pill with the routine's name and whether it's paused, with edit, open and delete.
- <a id="sk-12"></a>✅ **Routine run header.** A routine chat opens with a card giving the routine's name, when it ran and why (the scheduled time) and the run status, with open-routine and run-again. A run that caught up after the app was closed says so.

### Connectors

The sidebar's Connectors row opens atelier://connectors, and Settings › Connectors opens the same page. It starts in the More dropdown: a companion already works in the sites you have open, and setup connects the apps it offers.

- <a id="sk-13"></a>✅ **Connector directory.** The header counts the connected connectors, and a search box filters everything. Groups: connected, your custom servers, and a curated local directory of official remote servers grouped by category, each collapsed to a few rows with show more. Status and category filters apply. Connecting uses sign-in where supported, otherwise a URL and token. A deep link (atelier://connectors?connect=&lt;id&gt;) opens a confirmation banner. Icons are site favicons fetched at runtime or generic icons.
- <a id="sk-14"></a>✅ **Connector detail.** Description, directory or custom, connection health with Reconnect, rename, a label colour and remove behind a confirmation. Every tool gets a policy (ask each time, always allow, off) plus allow all, and the policy goes with every request; ask-first works only for locally run tools. Connectors that need settings (host, workspace) show those fields. Several accounts for one service are separate entries, one marked default. A local server shows its command and needs approval before its first start.
- <a id="sk-15"></a>✅ **Add a custom server.** A dialog takes a display name, an optional logo (image files only), and a transport: a remote URL (localhost allowed), a local command with arguments and environment variables you can add, reveal and remove, or a pasted JSON config for one or more servers. Advanced options take a bearer token or API key and an optional header name. Secrets are encrypted with the system keychain, and invalid entries name the wrong field.

### Apps

Apps are small tools the agent builds as sandboxed HTML artifacts, plus websites saved as apps and the apps packs bring ([apps.md](../apps.md)). They are a different thing from connectors, which is why the sidebar row for integrations is called Connectors.

- <a id="app-ui"></a>✅ **Apps that look like Atelier (Atelier UI).** Every app a companion builds is served with Atelier UI first in its head: the browser's own tokens in light and dark, the accent of the companion that built it, Inter, and `ax-*` components (buttons, fields, segmented controls, switches, lists, results, empty states, badges, notices, dialogs), in cascade layers so the app's CSS wins. Pack apps link it from the kit (`/__atelier/kit/1/atelier-kit/ui.css`) and the starters use it. build_app carries the design notes (use the tokens and components, design every state, format numbers, leave out gradients, glows, glass, emoji icons, card soup, edge stripes and all-caps labels); its result lists the design problems a check found and shows the draft in light and dark, so the model fixes it before it says it's done. The built-in skill App design has the long version ([apps.md › Atelier UI](../apps.md#atelier-ui)).
- <a id="ap-01"></a>✅ **Apps in one place, and in the sidebar your way.** An app is anything you open and use: a website saved as an app, an app or panel a pack brings, or an app a companion built. Workspace › Apps lists them under Websites, From packs and Made with your companions (a group shows only when it holds something; with none, one short note says how to get an app), with Get more apps (the Packs page's Browse) next to New app. Any app can show in the sidebar under the destinations as a row, as just its icon (a strip of logos above the rows, with the app's badge) or not at all: right-click it in the sidebar or in Apps, or pick it on its pack's page; drag to reorder, and drop on the strip to make it an icon. A pack's `sidebar: true` is only where its app starts. The choices are kept per profile (`sidebar.apps`); the sidebar options popover points to them. Packs are what you add to Atelier (the Packs page installs, reviews and updates them, and says that their apps are in Apps); New pack… builds one with a companion.
- <a id="ap-02"></a>✅ **A front door to Packs.** The Packs page is a sidebar destination like Skills and Connectors: in the More dropdown by default, a row of its own once shown in the sidebar options, opening on the destination surface. The main menu's tools have Packs next to Extensions and Passwords; the menu bar's Extensions menu has Packs… and Get apps and packs… after the Web Store's rows; Workspace › Apps has Get more apps next to New app; and Settings › Extensions is Settings › Extensions and packs, with Packs first. One path for each intent: use an app (Apps or the sidebar), get a new one (Get more apps), manage what you added (Packs).
- <a id="wa-01"></a>✅ **Websites saved as apps.** A tab's menu has Save as App: the site is kept as an app under its own name, start page and icon (its web app manifest when it has one, else its title, meta tags and favicon). It stays a web address; nothing is installed or converted. Workspace › Apps lists web apps above the apps companions built (open, rename, remove) and suggests the sites you visited at least 5 times in 30 days, search engines left out, each with Save as app. Opening an app goes back to its tab when one is open in any normal window (the tab it last opened first; anywhere on its site unless another app shares the site), else opens one at its start page. The command bar finds web apps by name or site under Apps. They aren't sidebar rows. Stored in userData/web-apps.json.

### Workspace

- <a id="ws-01"></a>✅ **Workspace in four tabs.** atelier://workspace is one centred column: the title with a Search everything field, then four tabs, Home, Projects, Files and Apps (← and → move between them), with Recently deleted (and how many items it holds) at the end of the tab row. Home shows the newest files, projects and apps, each with See all; with none of them, one empty state offers New project, Share a folder and New app. Files holds the shared folders, each companion's own files and, with the tables flag on, the tables (Import CSV, search, right-click to export or delete); a table opens on its own page with a back arrow to Files. On a tab's own view the tab names the section, so its head is a light row of a short description and its actions; a project, a folder, an app, a table, Search and Recently deleted have a back arrow and their title. Enter in the search field shows the results (atelier://workspace/search?q=), grouped by source, and typing there updates them. The Timeline is History's: with the timeline flag on, History has List and Timeline views (atelier://history?view=timeline&scope=…&date=…), and an old atelier://workspace/timeline address opens it there.

### Packs

A pack is the one unit you make, install, share and remix: skills, routine templates, site tweaks, accents, companions, connectors, panels, commands, page menu items and agent tools in one folder with a manifest. The full design is [packs.md](../packs.md).

- <a id="pk-01"></a>✅ **Pack format and validation.** `atelier-pack.json` (format, manifest version, id, name, version, description, author, built by, homepage, update address, remixed from, contributions, permissions) and its files. Every rule is checked with a reason naming where it is: safe relative paths, file count and size limits, files that exist, `run` targets that exist, sites covering every tweak, least privilege, readable (not minified) code, companions without memory, a newer manifest refused with a clear message.
- <a id="pk-02"></a>✅ **Packs page.** atelier://packs shows Your packs as cards and Browse, with Add (from a file, from a link, from a folder you're building) and New pack. Each card says what the pack is by the main thing it brings (an app, a game, a world, skills, a look, a companion, tools), with its tinted mark, who made it, one status when something needs you (needs attention, update ready, off, waiting, withdrawn), Open for its one app or world, and its switch; a filter by type shows when you have more than one type, and search filters by name, description and author. Packs a companion is still building sit above the cards under Being built, with Review and install (or Fix with a companion) and the rest in a menu. A card opens the pack's sheet: Open and on or off first, what needs you, what's inside (Open, Add routine, Add companion, Add connector, Use this accent, where its apps show in the sidebar), its keys and sign-ins, and what it can do; source, signature, version, services, commands and tools, files and log are folded under About this pack; Share or Export, Remix with a companion, Check for updates, Review update and Remove close it. Browse's community indexes are managed under Sources. Packs that come with Atelier can be turned off, not removed.
- <a id="pk-03"></a>✅ **Install review.** Every install, from any source, opens a review first: name, author, built by, source, signature, what it adds, the permission lines most serious first, problems that block it, what it tells the assistant (skill instructions, tool descriptions, and each offered companion's standing instructions, skills and routine prompts), every code file to read and the file list. Serious lines need a tick before Install. An update lists what it adds; going back a version is refused.
- <a id="pk-04"></a>✅ **Permissions in plain words.** Lines at four levels (adds, note, warning, serious): skills, templates, accents, companions, commands, panels; changes how sites look, notifications, clipboard; reads sites (or every site), sends requests to hosts, uses your model, gives the assistant tools, offers connectors; runs page scripts, reads and sends out, runs a program on this Mac.
- <a id="pk-05"></a>✅ **Data contributions.** Skills (read-only, From <pack>, a Packs segment on the Skills page; Duplicate to edit), routine templates (Add routine makes a paused routine), tweak CSS and scripts on the listed sites (never on sign-in or atelier:// pages), accents in Settings › Appearance, companions (through the companion import, never memory), connectors (added, then their page opens for a token; a local one still needs its first-start approval). Pack CSS loads nothing from elsewhere; pack scripts stay off sites with sign-in pages; nothing from packs runs in private windows.
- <a id="pk-06"></a>✅ **Sandbox and bridge.** Each pack's own partition and `atelier-pack://` origin, a strict CSP, no network, no permissions, no navigation or pop-ups, no Node. `window.atelier` (storage, page info, text and query on the pack's sites, fetch to its hosts without cookies, notify, ask, clipboard, open on its hosts, log) is checked in main for the sender, the pack and the permission on every call. No inline scripts, a dead-end proxy and no WebRTC, so nothing leaves but through the bridge. Pages are read only once loaded and re-checked after; private windows' pages are never read.
- <a id="pk-07"></a>✅ **Panels, commands and menus.** Panels open in a tab in the pack's sandbox. Commands are rows in the command bar's Packs group; menu items join the page menu for the page, a selection or a link. A run opens a panel, sends a skill, or asks the companion to use a tool, with the page as context.
- <a id="pk-08"></a>✅ **Agent tools.** A pack's tools are client tools (`pk_<id>_<name>`) on both engines, run one at a time in a hidden tool host in the pack's sandbox, with a one-minute limit and results treated as information. Not in private chats.
- <a id="pk-09"></a>✅ **Logs.** Bridge refusals, tool calls, panel and tool host errors and `atelier.log` lines, last 500, on the pack's page with Clear.
- <a id="pk-10"></a>✅ **Companions build packs.** `create_pack`, `write_pack_file`, `read_pack_file`, `test_pack` (validation, permission lines, panels loaded off-screen, tool calls in a throwaway sandbox against a signed-out page, with no network or model beyond what you granted an installed version) and `propose_pack` (a card with Review and install), plus `list_packs`. A companion can't install or grant anything. New pack starts a building chat; Remix and Continue with a companion start an editing one. The `pack-builder` experiment turns the tools off.
- <a id="pk-11"></a>✅ **Share as pack.** A skill, a site tweak, an app or a companion becomes a draft pack from its own menu or editor.
- <a id="pk-12"></a>✅ **Sharing without a backend.** Export makes a signed `.atelierpack` (Ed25519 author key in the keychain) and refuses files that look like secrets; someone else's pack keeps its author's signature. The first install pins the author; another author's or an unsigned replacement is refused. Install from a link, from a community index (an https JSON file; the download must match its SHA-256) and by double-clicking an `.atelierpack`.
- <a id="pk-13"></a>✅ **Updates.** A pack with an update address is checked daily while Atelier runs and on Check for updates. An update that adds nothing to approve applies on its own; one that adds permissions waits with a badge and Review update.
- <a id="pk-14"></a>✅ **Packs that come with Atelier.** Built-in skills (turning it off hides them) and a readable example pack (skill, panel, command, menu item, tool), off by default, for companions to read and people to remix.
- <a id="pk-16"></a>✅ **Sidebar panels and new tab cards.** A panel with `sidebar: true` gets a row (with the pack's icon) in the sidebar's Packs block that opens it beside the page; ⌘-click opens a tab. A pack's cards show on the new tab page under the ideas card: its card module runs in the pack's sandbox and returns a few lines that Atelier draws, and a click runs the card's `open`.
- <a id="pk-17"></a>✅ **The community index and the pack file.** Atelier comes with the Atelier community index (github.com/3SENN/atelier-packs: signed starter packs, readable sources, pinned author keys, checks on every pull request), added once and removable. `scripts/packs/pack.mjs` builds and signs packs outside Atelier. `.atelierpack` files have their own icon, a group picture of three companions, on macOS, Windows and Linux.
- <a id="pk-18"></a>✅ **A web server of the app's own.** `permissions.server` (`{}` for this computer, `{ "lan": true }` for the same Wi-Fi) with its review lines in plain words; `atelier.server.start/stop/status` (`url`, `lanUrl` and a QR code of it for the app's UI), static files from a pack folder, `onRequest` for dynamic routes, sockets from served pages to the app's page (`onConnection`, `send`, `broadcast`, `__atelier/client.js` that reconnects by itself), events batched on the pack event channel. Atelier owns the sockets: 127.0.0.1 unless the app declared and asked for the Wi-Fi, then HTTPS with a per-install self-signed certificate; an unguessable token in the path, private-network peers only, Host and Origin checks, limits on sockets, sizes and rates, safe headers only. It lives as long as the app's page (and stops on Stop, idle or the pack turned off); Atelier's bar over the app's tab says it is sharing, how many are connected, and has Stop, with a first-time macOS firewall hint. The phone-controller starter: a QR code to scan, motion and A/B/Home/pointer from the phone, buzz back. See [packs.md](../packs.md) › A web server of its own.
- <a id="pk-15"></a>✅ **Around Atelier.** Settings › Extensions has a Packs section; Settings › Notifications a Packs switch; the usage meter a Packs row; Settings › Your data counts packs and Reset Atelier clears them (the author key only with the secrets); the command bar offers the Packs page.

### Quick decisions

An optional decision model next to Atelier's built-in rules; off changes nothing. The full design is [decisions.md](../decisions.md).

- <a id="dc-01"></a>✅ **Rules first.** Every decision keeps its rule as the answer; the model takes over only when it is on for that use, the window or chat is not private, it answers within the use's time limit and is sure (per-use cutoffs). Compare mode keeps the rules and only notes where the model would have decided otherwise.
- <a id="dc-02"></a>✅ **Any providers, any models.** TypeSafe Jev, OpenRouter (its Decisions router: 36 decision models from many makers), Experiential Labs (Clef, Jev, GPT-6 Luna), OpenAI Decisions (GPT-6 Luna) and any number of servers of your own, connected at once, each with its own key; what each offers listed live with prices and data policy; your chosen models in order, the next answering when one fails, is busy or reaches its rate limit; one retry on 429/529, a pause per model after a rate limit with what the provider said, typed errors; System One refusals read as unsure.
- <a id="dc-03"></a>✅ **Settings › Quick decisions.** Its own page in the Agent group: one switch (off keeps the setup), one status and a line saying what to do next; providers (connect, change key, disconnect, get a key) and your own servers; your models in order with each one's state, Test, up, down, remove; Add a model from what the connected providers list (price, Free, no data kept, search) or by id; a model added and a provider connected are checked by themselves; how it's used; the switches in three groups, each saying what it sends and what it depends on; where it differed (newest 20, clearable, also in Your data). Model and key keeps one row saying whether it is on (with which model, how many, or that it isn't answering) that opens the page; Settings search finds it.
- <a id="dc-04"></a>✅ **Only what is decided about.** Only the text being decided about is sent (the end of a reply, a control's label with its page title and site, what you typed or said), cut to 24,000 characters, and nothing from a private window or chat. Keys are sealed per provider by this computer's secure storage and never sent to a page.
- <a id="dc-05"></a>✅ **Where it differed.** When a sure answer differs from the rule, Atelier keeps a row on this computer (the newest 200): the use, both answers, how sure the model was, whether it was used and a redacted excerpt. Settings shows the newest 20, and Your data clears them.
- <a id="dc-07"></a>✅ **Routine conditions and atelier.ai.decide.** "Only tell me if…" on a routine (editor and `propose_routine`), quiet only on a clear no; `atelier.ai.decide` for packs with its own budget on a decision model; both fall back to the Claude engine (your API key, or another engine). The `sorter` pack starter.
- <a id="dc-08"></a>✅ **Is a reply waiting on you.** With the rule, a reply needs you when its last line ends in "?"; with a sure model, only when the work is blocked on an answer.
- <a id="dc-09"></a>✅ **Plain dictation typed at once.** With "rewrite the field" on, plain dictation into a field is typed at once when the model is sure; edit requests still go to the companion.
- <a id="dc-10"></a>✅ **A second opinion on the companion's clicks.** When the English keyword list finds nothing, the model may add a stop in any language but never remove one, so page text can't talk its way past the guard. The same control on the same page is judged once every ten minutes.
- <a id="dc-11"></a>✅ **Setup picks.** Tech level, reply style and interests are settled by the model where it is sure, alongside setup's own extraction call.
- <a id="dc-12"></a>✅ **Search or ask, and who voice is for.** After a pause in typing, the new tab's top row (and Enter) becomes a search or a question; in auto voice mode, a request for the companion ("open my calendar") goes to it instead of the focused field.
- <a id="dc-14"></a>✅ **Search or ask in the address bar.** After a pause in typing, a sure "ask" moves the Ask row to the top and Enter asks the companion; never per keystroke, never for an address, never in a private window; a row picked by hand wins.
- <a id="dc-15"></a>✅ **Effort per message.** Off by default (it sends each message). A sure "no thinking needed" runs the turn at low effort, a sure "hard work" one step above the chat's effort; the model the person picked never changes; messages a person sent (typed, spoken or a selection) only, never routines or helpers, never in a private chat. Both engines.
- <a id="dc-16"></a>✅ **Which skills fit a chat.** At the first message, the companion's own skills that fit are listed first and marked; with the model off the prompt is unchanged. Connectors are not ranked: a chat's tools are fixed at its first message, so a connector left out could never be used later in that chat.
- <a id="dc-17"></a>✅ **What's worth remembering.** Off by default (it sends whole chats). Before the nightly tidy and "Build from past chats", chats the model is sure hold nothing lasting are skipped; a tidy with nothing left makes no Claude call. The count shows on the pass and the job.
- <a id="dc-18"></a>✅ **Group tabs.** From the tab menu, the strip's menu and the command bar: by site with the model off; by topic, or into the window's own groups, with it (only each tab's title and host are sent; at most 4 s of waiting, the rest by site). Pinned and grouped tabs stay, a joined group stays where it is; Undo.
- <a id="dc-19"></a>✅ **OpenAI's Decisions request.** GPT-6 Luna (OpenAI, or `gpt-6-luna-decisions` through a gateway) through the same questions and readers, translated both ways; a refusal leaves the rule.
- <a id="dc-20"></a>✅ **The slow tail.** A decision someone waits on with no answer after 250 ms is asked again and the first answer wins; never for batch uses (tabs, labeling, memory, routines, packs), never to a server on this computer, and never once a rate limit was met this session.
- <a id="dc-13"></a>✅ **Labeling and sorting for the companion.** `label_items`: the companion hands the same yes-or-no, pick-one or rating questions about up to 50 items (emails, products, results, rows) to the decision model, a few at a time; sure answers come back as verdicts, the rest as "unsure" with what the model leaned towards. Offered while a decision model is on and its switch is, never in a private chat; no Claude fallback (the companion judges the items itself). Both engines.
- <a id="dc-06"></a>✅ **Measured.** A labelled set per decision and for labeling (several languages) that runs against a real model with accuracy, unsure rate, option-order checks, answer times, and Atelier's rules alone next to rules with the model.

## Meetings and voice

### Voice

- <a id="mv-01"></a>✅ **Hold-to-talk.** An opt-in setting, off by default. While Atelier is focused, holding the voice key (⌥Space, or another chord from a short list) records through the native speech helper, and releasing ends the turn. Holding is detected from input events inside Atelier, never by system-wide monitoring. Holding ⇧ as well makes the answer be spoken. A screenshot of the tab is taken when recording starts. The feature reports itself unavailable when the helper is missing or permission is denied.
- <a id="mv-02"></a>✅ **Quick ask launcher.** An optional global shortcut (⌥Space, off by default), registered as an ordinary shortcut with no input monitoring, toggles a small frameless launcher. The launcher floats above every app and space, centred near the bottom of the display the cursor is on. When it opens, it remembers the frontmost app, can capture the current display (this needs Screen Recording permission), and starts listening. Pressing the key again while listening stops and shows the text; pressing it at any other time hides the launcher and returns focus to the previous app. Esc dismisses it.
- <a id="mv-03"></a>✅ **Launcher contents and sending.** One input shows the live partial transcript, then the final text. A screenshot chip attaches or removes the capture, and the choice is remembered. Controls: start and stop listening, switch to typing, send, close and key hints. States: listening, transcribing, sending and working. Errors: microphone blocked (with a link to privacy settings), another recording already running, and recording failed. Sending starts a new chat with the current companion in a new foreground tab, attaching the screenshot unless removed, and opens a window if none is open. If a meeting recording is running, its transcript page opens instead.
- <a id="mv-04"></a>✅ **Voice HUD.** A floating HUD with a live microphone level and the transcript, split into settled and still-changing text. States: listening, thinking (with rotating status words), answered (a short preview with light Markdown and citations), speaking and error. Controls: dismiss, open the chat, read aloud or again, copy text that failed to insert, cancel queued commands, and switch where the command goes. A countdown ring closes it unless hovered, and a hint invites holding the key again to reply. Its tones are generated in code and have their own toggle.
- <a id="mv-05"></a>✅ **Where a voice command goes.** A command goes into the focused text field as dictation (the HUD says so) or to the companion, and you can switch between them. Optionally, a command aimed at a field rewrites the field's contents with a quick model call. A command spoken while another is running waits in that chat; commands don't run in parallel.
- <a id="mv-06"></a>✅ **Voice errors.** Separate errors, each with an action: microphone blocked (link to privacy settings), microphone busy, no speech heard, recording failed, no field to type into, insert failed (offers to copy the text), no API key (link to Settings) and a generic failure.
- <a id="mv-07"></a>✅ **Dictation in the composer.** A mic button starts on-device dictation through the helper, with listening and transcribing states, a level indicator and a stop control, and inserts the final text at the cursor. The first use requests microphone and speech permission, and a denial comes with instructions for fixing it.
- <a id="mv-08"></a>✅ **Transcription errors.** Clear states for: the helper missing or failing to start; microphone or speech permission denied (link to settings); Screen Recording missing for the other side of a call (recording continues with the microphone only); recognition interrupted (restarts by itself); and an unsupported language.
- <a id="mv-08a"></a>◐ **Newer on-device transcription engine.** On macOS 26, dictation, meetings and file transcription run on Apple's SpeechAnalyzer with SpeechTranscriber, which has no one-minute limit per request: each source (microphone for you, system audio for them) keeps one analyzer for the whole session. Live text shows as it is recognised and is replaced by final text, split into segments at pauses; an engine failure shows reconnecting and restarts. Custom vocabulary ([ST-19](#st-19)) goes in as the engine's contextual strings. Older macOS versions, languages the newer engine doesn't support (Dutch among them) and a language whose model is still installing use SFSpeechRecognizer as before. A model installs the first time its language is used; a start waits up to 2.5 seconds for it and otherwise uses the older engine that once. The helper's `started` line and its language list say which engine runs (`engine`), and `prepare` with its `assets` progress lines are additive to the protocol. Gap: proven with fakes and state-only helper queries; accuracy, the first install and whether vocabulary helps need a supervised live test.

### Meetings

- <a id="mv-09"></a>✅ **Meeting card.** A separate always-on-top card in the bottom-right corner of the display, excluded from screen capture, appearing about three seconds after its trigger. Modes: a tab opened a known video-meeting site (once per meeting URL), offering record, join only, or settings; a calendar meeting is about to start (through the calendar helper), offering join and record; a meeting is due but permissions are missing, offering set up and do-not-show-again; and a long recording is still running or has gone silent, asking whether to continue, with a countdown to an automatic stop. While that last question is up, the other modes wait. Each card has dismiss and a small menu to mute this kind of card, this site, or all meeting cards. The card moves when the display setup changes.
- <a id="mv-09a"></a>◐ **Calls in desktop apps.** When a call starts in Zoom, Microsoft Teams (new and classic), FaceTime, Webex, a Slack huddle, Discord or an installed Google Meet web app, the meeting card offers to take notes ("Zoom call — take notes?"), with a system notification and its Take notes button while Atelier is in the background. The speech helper reads which processes have the microphone open from Core Audio's process objects (macOS 14.4+) and which apps run from NSWorkspace: no permission, no prompt, nothing recorded. The microphone has to stay on for three seconds (an app checking its microphone is not a call), short gaps are ridden out, a mute that keeps the call's sound keeps the call, and the call ends 20 seconds after both stop or when the app quits. Atelier's processes never count, and each call is offered once. Taking notes records the microphone plus only that app's sound, through ScreenCaptureKit filtered to the app (the Screen Recording grant the checklist already asks for; a Core Audio process tap would need a second permission), names the meeting after the calendar event happening now when one matches, and wraps up when the call ends. FaceTime plays call audio from a system service, so its calls record the Mac's sound. Settings › Transcription has the switch and one per app. Gap: proven with fakes only; a supervised live call should confirm the per-app audio filter (Electron and web-app helpers, FaceTime) and the end timing.
- <a id="mv-10"></a>✅ **Recording widget.** A small always-on-top widget on the right edge of the display the cursor is on. It can be dragged, shows on every space and over full-screen apps, is excluded from screen capture and stays inside the work area. It appears only while a recording runs and the place it was started from is out of view, after a short debounce. It shows elapsed time and live level bars, with pause and resume, stop, and a drag handle on hover. Pause needs a new helper command.
- <a id="mv-11"></a>✅ **Wrap-up card.** After stopping, the widget grows into a card with a processing state. It then offers to discuss the meeting with a chosen companion, view the summary, open Meetings, or dismiss. Without an API key the transcript is still saved, and the card says the summary will follow once a key is added.
- <a id="mv-12"></a>✅ **Meetings page.** atelier://meetings lists meetings and standalone recordings with search, plus a live row for the transcription in progress with a stop control. Each row can summarise (title, summary, decisions, action items), transcribe again after a failure, attach to a chat, export, or delete with confirmation. It has empty and loading states.
- <a id="mv-13"></a>✅ **Meeting detail.** The summary with takeaways and participants, then the transcript as bubbles labelled by audio source (you or others), with labels renamable per meeting. Labels follow the audio source because the helper doesn't tell voices apart. With recording on there is an audio player with seeking and play-from-segment. A banner shows while transcription runs, and ask-about-this-meeting opens a chat with the meeting attached.
- <a id="mv-14"></a>✅ **Send waits for a transcript.** If a meeting is attached while its transcript is still being finished, the message is held behind a cancellable waiting chip and sent once the transcript is ready.

### Framework

- <a id="st-01"></a>✅ **Grouped navigation.** The groups above, with the active row highlighted and the breadcrumb showing Settings / &lt;page&gt;. Rows for a disabled experiment or another platform are hidden rather than greyed out.
- <a id="st-02"></a>✅ **Collapsible, resizable nav.** A button collapses the nav to an icon rail. When expanded, a drag handle resizes it within limits, and ←/→ on the focused handle change the width in small steps. The nav collapses by itself when the content card is narrower than about 960 px, skips the animation under reduced motion, and remembers its width.
- <a id="st-03"></a>✅ **Routes and aliases.** atelier://settings opens the first page and rewrites the tab URL, so back, forward and the breadcrumb agree. Old or alias names redirect to the page that now holds the setting, and unknown pages fall back to the default with no error. Deep links can carry a query that opens a flow (atelier://settings/import?browser=&lt;id&gt;).
- <a id="st-04"></a>✅ **Page kit.** Every page has a title and a one-line description. Content sits in cards of rows: a title, a description and a control on the right (switch, select or button), and for switches the whole row is clickable. Loading pages show skeleton rows, and a failed load shows an inline error with Retry. Long pages can link to the matching guide.
- <a id="st-05"></a>✅ **Finding settings.** Settings has no search box. The command bar indexes every settings page and the main individual settings by keyword, and choosing one jumps to the page and highlights the row. Long lists (extensions, passwords, connectors) have their own filter field.
- <a id="st-06"></a>✅ **Settings registry and scopes.** Each setting is registered once with a schema, a default and a scope. App-wide: interface zoom, picture-in-picture, downloads, warn before quitting, notifications. Per profile: theme, accent, layout, search engine, ad blocking, website languages, bookmarks bar, sidebar options. A new profile starts from the defaults, changes reach every window and overlay at once, invalid stored fields fall back one by one, and secrets stay encrypted separately. There is no sync.

### You

- <a id="st-07"></a>✅ **Local you card.** Your name (the companion uses it, and the sidebar footer shows its initial) and an optional avatar picture from a file, kept locally, with inline errors for non-images and oversized files. It also shows whether an API key is set, with a link to Model and key. There is no email, sign-in or sign-out.

### Companions

- <a id="st-08"></a>✅ **Companions page.** Lists every companion, hidden ones included, each opening its profile card, plus create ([CO-12](#co-12)), add from presets ([CO-15](#co-15)) and import ([CO-14](#co-14)).

### Dock icon

- <a id="st-09"></a>✅ **Dock icon choice.** On macOS, previews of the standard Atelier icon and of each companion form a keyboard-navigable radio group, with a status line and spinner while the icon re-renders. ### Transcription

- <a id="st-17"></a>✅ **Setup checklist.** A one-time checklist of the macOS permissions meetings need: microphone, speech recognition and screen recording (for other participants' audio). Each has a grant button that asks the OS or opens the right System Settings pane, then rechecks every few seconds through the helper's permission report. Finished steps are checked, and the checklist hides when all are done.
- <a id="st-18"></a>✅ **Microphone and language.** A microphone select (built-in by default, the system default, or any input) with refresh, used for meetings, dictation and the level test. A recognition-language select, defaulting to the system language, lists only locales the recognizer supports and marks the on-device ones; a second language is One language only (the default), Automatic, or chosen ([ST-18b](#st-18b)). If the saved mic is unplugged, the default is used with a notice. On macOS 26 the language row also shows the newer engine's model for that language ([MV-08a](#mv-08a)): preparing with a percentage, ready, or a Prepare now button (with Try again after a failure).
- <a id="st-18b"></a>✅ **Bilingual meetings.** Meetings, online and in person, listen in a second language at the same time as the first: both recognizers hear the same audio, every line carries the language it was heard in, how sure its recognizer was (confidence) and how well its text reads as that language (Apple's language recognizer, on the Mac), and for each sentence or clause Atelier keeps the language that fits, mostly by confidence (a recognizer forcing the other language into its own words writes fluent-looking text it is unsure of). A line stays when it scores better over at least half of its time; a near tie goes to the first language. One speaker switching between sentences, or between clauses with a short pause, gets each part in its own language; English mixed inside a Dutch sentence comes out as the Dutch recognizer heard it (common English words survive, whole English phrases can be misheard), since Apple's recognizers each listen in one language. Live captions follow the language that won last; finals settle once the other language has caught up, or after 4 s. A recording transcribed from a file is heard once per language. Settings › Transcription's Second language is One language only by default; Automatic takes the next of the Mac's preferred languages in another language (e.g. English (Netherlands) then Dutch gives English and Dutch), or pick a language. Settings saved before 1.3.2 with Automatic move to One language only once. Dictation stays in one language. When on-device recognition starts over mid-file (a long pause, or speech it can't follow), the text before is kept. Summaries of mixed meetings are written in the language most of the meeting was in. macOS only; Dutch (Netherlands) runs on this Mac, Dutch (Belgium) uses Apple's servers.
- <a id="st-18c"></a>✅ **Record audio only.** Settings › Transcription › Meetings chooses what recording a meeting does, as two illustrated tiles: Transcribe and take notes (the default: a live transcript, then the companion's notes) or Record audio only (just the audio, in person or online, both sides of a call as usual; no transcript, notes or Speech Recognition prompt). Audio only always keeps the audio, so Keep audio recordings shows on and fixed. It is also the fallback when this Mac can't transcribe: with Speech Recognition off for Atelier, or a language the recognizer doesn't support, a meeting records audio instead of failing, and says why (the recording widget's captions-off icon opens Transcription settings; the meeting page says Speech Recognition is off, with Allow Speech Recognition, or that the language isn't supported). Meeting cards then offer Record instead of Take notes, a permissions card with only Speech Recognition missing offers Record audio only, and a desktop call's notification has Record. An audio-only meeting is listed as Audio only with its player, Transcribe (which transcribes it from the audio, then writes the notes as usual and makes it an ordinary meeting) and Export audio; it has nothing to summarise, attach or export as Markdown, and a chat it reaches says there is no transcript. The wrap-up says Recording saved, with Open recording. Without the microphone nothing can be recorded, so that still fails with its fix. Quitting Atelier mid-recording stops the recording first, so what was recorded is saved rather than thrown away: the recording widget shows Finishing… while it saves (up to 2 minutes, the broker's own limit for a stop), a second ⌘Q waits for the same save, and an update's restart (its card already asks about a running meeting) stops and saves the recording before it installs. A crash, force quit or power loss mid-recording keeps what was recorded: the helper writes each source as an ADTS AAC part (each frame stands alone, so a part that was never closed is still readable; its start is in its name), and on the next start the library has the helper put the parts back together (`recover`), with the meeting waiting as Saving the recording… until it is a recorded (or, with a transcript, transcribed) meeting again. Parts it can't rebuild stay for the next start; a failed merge at stop keeps its parts the same way. Keep audio recordings is on by default from 1.3.2 for new installs; an existing install keeps its own setting.
- <a id="st-19"></a>✅ **Custom vocabulary.** A text area for names, products and jargon (one per line or comma-separated), passed to the recognizer as context hints (contextual strings on either engine). Empty by default, length-limited and trimmed.
- <a id="st-20"></a>✅ **After-meeting summary and alerts.** An auto-summarize switch, on by default: when a meeting ends, the companion titles it, labels the speakers and writes a summary with action items. Off, only the transcript is saved, with summarize later. Two alert switches: before calendar meetings (needs a calendar connector or the D helper) and when a meeting site opens in a tab. A third, on by default, offers notes for calls in desktop apps ([MV-09a](#mv-09a)), with a switch per app; it needs macOS 14.4 or later.
- <a id="st-21"></a>✅ **Capture levels and test.** Sensitivity sliders for the microphone and system audio, each with a live meter. A test records without transcribing, and the last test can be played back or deleted. Reset restores defaults, and changes apply from the next recording.

### Privacy

- <a id="st-35"></a>✅ **Ad and tracker blocker.** A switch that turns blocking on or off live, on by default, with per-site exceptions ([SH-37](#sh-37)), a main-menu toggle and per-profile values.
- <a id="st-36"></a>✅ **Clear cache, cookies and site data.** Two actions, each with its own confirmation and inline spinner, then a toast. Clear cache removes the HTTP, code, service-worker cache-storage and host-resolver caches and keeps cookies. - <a id="pv-01"></a>✅ **HTTPS-First.** On by default (Settings › Privacy › Secure connections). A tab's top-level `http://` navigation on the default port goes to `https://` first, in the webRequest mux (`src/main/privacy/httpsFirst.ts`). When the secure version fails (no TLS, a certificate or TLS error, a refused, reset or timed-out connection, an empty answer, a redirect loop, or an https answer that redirects straight back to http), the tab shows Atelier's "This site doesn't support a secure connection" page at the http address with Continue to site (remembered for the site, per profile; memory only in private windows) and Go back; ⌘R on it shows it again. Never upgraded: localhost and `*.localhost`, IP literals, `*.local`, `*.home.arpa`, single-label and unregistrable names (`.test`, `.lan`, `.internal`), other ports and the smoke server. The sites allowed without HTTPS are listed with Remove. A bare host typed in the address bar (`example.com`, no scheme) goes to `https://` as before; when that fails the same way, the same page offers its `http://` address (a remembered Continue goes straight there), and site info doesn't call it upgraded.
- <a id="pv-02"></a>✅ **Hide cookie banners.** On by default. A built-in list of the common consent tools (`src/main/privacy/cookieBanners.ts`) becomes an injected stylesheet of `!important` hiding rules on every page (it also unlocks scrolling the tool locked) plus an isolated-world script that presses the tool's own Reject all or Only necessary button once, never Accept. Optional community lists (EasyList Cookie List, uBlock filters – Cookie Notices) are switched on per list, downloaded from their maintainers only then, refreshed weekly and never bundled; Ghostery's parser reads them and only plain hiding rules are kept. A per-site switch in site info (and a list in Settings with Remove) leaves a site's banner alone; changes apply to open pages at once.
- <a id="pv-03"></a>✅ **Global Privacy Control, consistently.** With the switch on, `Sec-GPC: 1` goes with every request and `navigator.globalPrivacyControl` is true in every frame, iframes included. Account sign-in pages keep the engine's own world, so they get neither the property nor the header. Workers send the header only.
- <a id="pv-04"></a>✅ **Privacy on this site.** The site info popover ([SH-37](#sh-37)) adds how the page was reached (HTTPS, upgraded by HTTPS-First, or not encrypted, with why), how many ads and trackers the blocker stopped on this page (or that blocking is off there), and what happened to its cookie banner (refused, hidden, none, shown on this site), with the per-site banner switch.

- <a id="st-52"></a>✅ **Activity memory retention.** The rules are shown on the page (screenshots about a month, raw captures about three months, written notes until you delete them), each shortenable. A daily cleanup applies them, and runs again when you shorten a limit.

### Storage

- <a id="st-53"></a>✅ **Storage overview.** The total used and a stacked bar by category (chats, chat attachments, memory, history, website data, meeting recordings, activity memory), with tooltips and an accessible legend in colours that work in both modes. A progress state shows while sizes are measured, and an error offers Try again.
- <a id="st-54"></a>✅ **Free up space.** Clear cache (confirmed). Remove chat images older than 30 days, keeping the text (confirmed). A per-chat list by size offers delete chat or delete its images, each confirmed, and sizes refresh afterwards.
- <a id="st-55"></a>✅ **Reset Atelier.** A danger-zone card. It stops the agent and routines, wipes browsing data, chats, memory, companions, caches and site data, and restarts into the welcome flow, after you type a confirmation phrase. A checkbox (off) also deletes the saved API key and the password vault.

### Experiments

- <a id="st-57"></a>✅ **atelier://flags.** Experiments newest first, each with its date, a short description and a select of allowed values. Dependencies are shown and enforced (a child is off and locked while its parent is off), and changes that need a restart offer to relaunch. All local.

## Overlays and dialogs

### Overlay layer

- <a id="ov-01"></a>✅ **One overlay view.** A transparent view above the tab views draws every floating surface. Main sizes it to the open surface, or the whole window for modal ones, and lets clicks pass through when nothing is open. Each surface declares its anchor (window or tab), size (fixed or fill), outside-click behaviour (close or ignore), whether it blocks the page, and what a tab or space switch does (close, follow its tab, stay, or hide until its tab returns). Unknown surface ids are rejected.
- <a id="ov-02"></a>✅ **Exit animation and stacking.** Surfaces play a 150–250 ms exit before removal, skipped under reduced motion, with a safety timeout so a stuck animation never leaves a dead layer. Stacking order: modal dialogs, then the command bar and menus, then toasts, hover cards and bubbles.
- <a id="ov-03"></a>✅ **Warm surfaces.** The overlay view is created hidden at start-up, so its first paint is instant. Hovering or focusing a toolbar or sidebar button mounts that surface and loads its data, so a click shows full content in the first frame.
- <a id="ov-04"></a>✅ **Live theme everywhere.** Every Atelier surface reads the same tokens and switches live, including the separate always-on-top windows for voice, meetings, the recording widget and the drag ghost, which rely on the media query and tokens. Anything Atelier draws inside pages follows the app theme, not the OS.

### Toasts and tooltips

- <a id="ov-05"></a>✅ **Toasts.** A small toast at the top centre of the tab confirms copy actions and shows errors, for about two seconds or until a tab switch. Actions behind it: copy page link (⇧⌘C), copy as a Markdown link, copy the page as Markdown, copy a screenshot of the tab, and copy a link to the highlighted text (with an error toast when no link can be made). It also confirms bookmarks, downloads, routines and saved passwords. The error variant is wider, a two-line variant fits longer text, and destructive actions get Undo.
- <a id="ov-06"></a>✅ **Tooltips.** Toolbar and sidebar tooltips are drawn in the overlay view so they can sit over pages. They fit a maximum size, include the shortcut as platform-formatted key caps, and follow the theme.

### Dialogs

- <a id="ov-07"></a>✅ **Dialog layer.** One dialog layer per window. A dialog is built from parts: title, description, optional icon or image, a callout, a text input, a checkbox and buttons. Each button has a style (primary, secondary, outline, ghost, destructive, link), an alignment, and optionally Esc or Enter. A dialog belongs to the window or a tab; a tab dialog blocks only that page and follows the tab, and it can close when focus leaves. One shows at a time and the rest queue, with duplicates dropped. Close, Esc and a backdrop click count as cancel. Focus is trapped with proper dialog roles, and a dialog that fails to render shows a plain fallback.
- <a id="ov-08"></a>✅ **Dialog kinds.** Generic confirm (cancel plus an action that may be destructive) and alert, callable from the chrome and main. Sign-in for HTTP and proxy authentication. Styled page `alert`, `confirm` and `prompt`. The save-login card and the problem report.
- <a id="ov-09"></a>✅ **Confirmations and small prompts.** Confirm before quitting or closing a window with several tabs (a setting, on by default), before deleting a chat, skill, routine, memory file or connector, and before clearing history (or offer an Undo toast). Rename a window or a chat, create a bookmark folder, and skip the rest of setup. Start a local MCP server with the exact command shown, and open at login with a link to System Settings.

### Permissions, devices and full screen

- <a id="ov-10"></a>✅ **Permission policy.** Silently allowed: sanitized clipboard writes, pointer and keyboard lock, persistent storage, protected media, wake lock, sensors and fullscreen. Silently denied: XR, background fetch and periodic sync, window management, web-app install and system wake lock. Asked: camera, microphone, location, notifications, clipboard read, local fonts, idle detection, device classes, speaker selection, local network and opening external apps. Some answers can only be remembered as deny (MIDI, screen capture, file system), and external-app links only as allow. Mail links open without asking, and Atelier pages get clipboard access.
- <a id="ov-11"></a>✅ **Site permission prompt.** A small prompt anchored under the pill's site-info button and tied to the tab that asked, hidden while another tab is active. It names the site and the capability, or the app it wants to open. Esc denies and Enter allows, and where the policy allows it there is a choice to remember. Remembered answers persist per site and profile (never in a private window); one-off answers last for the tab's session. Identical simultaneous requests share one prompt.
- <a id="ov-12"></a>✅ **Requests on agent-controlled tabs.** While the agent controls a tab, permission, screen-share, device and full-screen requests are denied at once, and the agent's next result says a person needs to take over and retry. A prompt closes if its tab closes or the agent takes control while it is open.
- <a id="ov-13"></a>✅ **Full-screen notice.** When a page goes full screen ([SH-05](#sh-05)), a pill at the top centre names the site (or says this page) and says Esc exits, then fades after about three seconds. The page context menu offers exit full screen.
- <a id="ov-14"></a>✅ **Screen share picker.** A modal picker for tabs, windows and screens, each with a fresh thumbnail (or a placeholder) and an app icon. Tabs come from the same profile across all windows, most recent first, never agent-controlled. A tab-audio toggle appears when audio is requested. A click selects, a double-click shares, and cancel and share sit at the bottom. Agent requests are refused. The picker closes if the requesting tab navigates or closes, a shared tab stays alive until capture ends, and missing Screen Recording permission gets a clear message.
- <a id="ov-15"></a>✅ **Device chooser.** A modal chooser per device class (USB, HID, serial, Bluetooth) with a live list, searching and nothing-found states, connect and cancel, and remember for this site. Bluetooth pairing supports confirm, compare PIN and enter PIN. It hides while its tab isn't visible and refuses agent-controlled tabs.
- <a id="ov-16"></a>✅ **Extension install prompts.** The same prompt lists what an extension will be able to do (or that it needs nothing extra), asks again for optional access later, and shows an acknowledge-only notice for unsupported extensions.

### Downloads

- <a id="ov-17"></a>✅ **Downloads popover.** About 300 px wide, from the toolbar button. Recent downloads, each with a file-type icon, name, progress (amount, percent, speed, time left) and a failed or cancelled status. A running download can be cancelled, and a finished one revealed, opened with a click, or dragged out as a file. A header clears finished items and links to the Downloads page. It has loading and empty states.
- <a id="ov-18"></a>✅ **Popover opens by itself.** For downloads you started, when the download begins after you chose where to save it, or when the file is under about 10 MB. Agent downloads never open it; they are reported in the agent's next result.
- <a id="ov-19"></a>✅ **Fly-to-button animation.** A click-through animation flies the file-type icon along a curve from where the download started to the downloads button, ending in a small bounce. It lasts at most two seconds, several can run at once, it is drawn in the overlay view, and it is skipped under reduced motion and cancelled when the window hides, moves or changes full screen.

### Page helpers and the agent

- <a id="ov-20"></a>✅ **Selection chip.** Selecting text shows a small chip beside it with ask the companion, explain, copy and search, plus a shortcut hint (⌘J with text selected). The page preload reports where the selection is. Ask quotes the selection, with its links and source URL, as a chip in the composer, and Explain sends a ready-made request. The chip hides on scroll, an outside click or a collapsed selection, and never appears on agent-controlled tabs.
- <a id="ov-21"></a>✅ **Agent notice.** A draggable floating notice over an agent-controlled tab (its position remembered per tab) shows which companion is in control and what it is doing: reading, working, paused, or waiting for you to solve a check. Actions: take over (pauses the agent and hands you the tab), hand back, open the chat, stop, and toggle side by side. On a human-verification challenge it asks you to solve it, offers skip page, open chat or stop, and confirms briefly once solved. It uses the companion's accent and stays legible on light and dark pages.
- <a id="ov-22"></a>✅ **Agent input shield.** While the agent drives, a transparent layer in the overlay view catches pointer input, shows a not-allowed cursor and a soft inner glow in the companion's accent, and draws the agent's cursor. A click is reported and brings up take over. The shield shows only while the agent is in control or resuming after a challenge, and page scripts can't remove it.
- <a id="ov-23"></a>✅ **Site suggestions.** When the site matches an enabled connector or a known app link, a dismissible card in the panel (or a small toolbar popover) offers to connect it or one to three ready-made tasks, drafted into a new or existing chat. It can be snoozed or turned off per site or everywhere, shows a clear message if drafting fails, updates when the page or chat changes, and is opt-in.
- <a id="ov-24"></a>✅ **Activity memory status.** A popover showing on, off, paused or outside active hours, saying captures stay on this device. It pauses for 15 minutes, an hour, three hours or the rest of today, or turns on until tomorrow, and links to settings.

### Autofill

- <a id="ov-25"></a>✅ **Fill popup placement and safety.** Fill popups open below the focused field, flip above it when there is no room, stay at least 8 px inside the tab, and hide while the field is scrolled away or another modal surface is open. A pick only counts once the popup has been visible and still for about half a second (restarted after any move or resize), to guard against clickjacking. This applies to password, card and address popups, including inside nested and cross-origin frames.
- <a id="ov-26"></a>✅ **Password popup.** Opens only on tabs you drive, when the preload reports a focus you started on a username or password field, with logins saved for that exact origin. It is skipped when both fields are filled, when nothing matches and you've started typing, and on username-only pages with no applicable login. A saved username found in the page is preselected, and arrow keys and Enter in the field drive the popup. Rows show the site icon, the username (or a placeholder) and when it changed. New-password fields offer a generated password, with use it or write your own. A link opens Passwords filtered to the site, and an empty state says nothing is saved. A passkey row is designed in but hidden: builds signed with Apple's browser passkey entitlement offer passkeys through the system's own sheet instead ([release.md](../release.md#browser-passkeys-and-icloud-passwords)). It closes on scroll, navigation, zoom, hide or close, an outside click, the tab going inactive, a pick, or the agent taking over.
- <a id="ov-27"></a>✅ **Save-login card.** After a login form submits and the page navigates, the vault checks whether the login is new or changed. If so, and the site isn't on the never-save list, a non-modal card at the tab's top right shows editable username and password fields with show/hide, plus never for this site, dismiss (Esc) and save or update (Enter). It never appears on agent-controlled tabs, is withdrawn if the agent takes over, can be turned off, and confirms with a toast.
- <a id="ov-28"></a>✅ **Split logins.** Per tab, Atelier remembers the username typed on the first page of a split login, so a password-only page can fill it and the save offer includes it. The last typed credentials for a URL are kept briefly, so the offer works after the form disappears. A filled or typed login is marked used. Nothing is kept after the tab closes.
- <a id="ov-29"></a>✅ **Card and address fill.** Card fill works only on secure pages without a certificate exception. Card fields are found from autocomplete tokens first, then labels, names and placeholders, and birthday fields are never treated as card fields. A focused card field lists saved cards by network and last four, naming the frame's site and the embedding site in cross-site frames. A pick needs Touch ID, then fills number, name and expiry (one field or month and year); the code is never stored, and the agent can never trigger or read a fill. After a secure checkout, a card offers to save the holder name, masked number and expiry; each dismissal is a strike, and after three for the same card and site it stops. Address fill recognises name parts, company, street lines, city, region, postal code, country, email and phone. It lists saved entries by name and first line, and after a submit with enough data offers to save them as contact and address sections.
- <a id="ov-30"></a>✅ **Problem report.** A dialog with a description (pasted images allowed), and options to add files, include the current chat and include a tab screenshot taken at send time. It says local logs are included. It needs no server: it saves a bundle on disk, reveals it, and opens an email draft (⌘↩), with busy states and the attachment size. It opens from Help and ⇧⌘H.
- <a id="ov-31"></a>✅ **Password import hint.** On a login page with no saved login, if you have never imported passwords, a one-time dismissible hint points to the CSV import. The dismissal is remembered.

### Files

- <a id="ov-32"></a>✅ **File viewer.** A viewer over the tab opens local files (Markdown, code, sandboxed HTML, images, PDF, audio, video, or a placeholder for binaries), agent reports, memory files, skills (frontmatter as a header) and meeting transcripts. Actions: edit (it can open straight into edit mode), export, open in a tab, open as an artifact, rename, delete (restorable from Recently Deleted) and reveal. It has error states for a missing file, a failed load or save, and a report still being written, and it closes with its tab.
- <a id="ov-33"></a>✅ **Version history.** A side panel in the viewer lists a file's earlier saves, marks the current one and labels each (saved, restored, deleted, moved) with a time. Picking one previews it, and it can be restored. States: loading, none, and error with retry.

## States

- <a id="ss-01"></a>✅ **Loading.** Lists and popovers show skeleton rows, and spinners are kept for short waits. Page loads get a thin progress bar in the overlay with a slow-load notice (over 8 s) and Stop. Until the window's layout has loaded, a placeholder shell is drawn, with its own failure state. The window opens only after the chrome paints, on a background matching the theme.
- <a id="ss-02"></a>✅ **Empty states.** Every list has its own short message with an icon and, where it helps, a main action: fill suggestions, logins, cards, addresses, downloads, bookmark folders, chat files, file versions, chats and chat matches, routines, extensions, history, search results and devices.
- <a id="ss-03"></a>✅ **Chat error cards.** Each error maps to an icon, a tone (info, warning, error) and an action (retry, open settings, change model, new chat, or none). Types: no connection; rate limited or overloaded (automatic retry with a countdown); service unavailable; model unavailable or not allowed for this key; request or message too large; chat too long (new chat, or compaction); refusal; key missing or rejected; quota or billing at the provider (link to the API console); and disk full. Retry re-sends the last turn without duplicating the message.
- <a id="ss-04"></a>✅ **Chat page states.** Skeleton rows while a chat loads; a could-not-load state with Retry and New chat; a not-found state for deleted chats, linking to All chats; and an offline banner that keeps the composer usable and holds sending until the connection returns.
- <a id="ss-05"></a>✅ **Save failure notice.** If writing a chat to disk fails, the chat shows an inline notice with Retry instead of only logging a warning (`#persist`).
- <a id="ss-06"></a>✅ **Online and offline.** One online state in main follows the network and reaches every surface. When the connection returns, the chat drops its offline notice and retries the pending request, error pages retry automatically, and connectors show reconnecting with a countdown.
- <a id="ss-07"></a>✅ **Failed, crashed and sleeping tabs.** A load failure becomes a styled Atelier error page (reason, URL and code) with retry. A crashed tab shows a crash page with Reload, and an unresponsive tab offers Wait or Reload. A tab put to sleep to save memory reloads when selected.
- <a id="ss-08"></a>✅ **Chrome crash recovery.** One renderer draws the sidebar, toolbar and every atelier:// page, so a crash blanks the window. On `render-process-gone` or a failed load of the chrome (or of the overlay view), Atelier reloads it. After repeated crashes, a limit stops the restarts and shows a minimal page with a retry button.
- <a id="ss-09"></a>✅ **Chat store migrations.** When an update changes the chat file format, chats migrate in place in versioned steps. A chat that fails to migrate opens with a notice offering retry or reload, and Settings › About Atelier lists the results.

Approval notifications stay until handled and offer allow and deny on macOS; reconnect notifications add open settings. Clicking one focuses the right window, tab or chat, a chat's notifications clear once it is viewed, each chat can be muted, and permission is requested the first time one is needed.

- <a id="ns-04"></a>✅ **Intro and system sounds.** The setup intro can play a few sounds timed to its animation through Web Audio at a modest volume, muted when sounds are off or reduced motion is on. A failed menu command, such as reopening when nothing was closed, plays the system beep. Voice has its own tones ([MV-04](#mv-04)).

## Onboarding and first week

- <a id="on-01"></a>✅ **Setup that resumes.** Setup is a fixed sequence of steps, saved locally after each step, so a restart resumes where you left off. Steps can be revisited; you can skip the rest after a confirmation or start over with a new companion. A step that hasn't loaded after about 45 s logs a local warning and offers to continue.
- <a id="on-02"></a>✅ **Animated intro.** A short staged intro: the Atelier mark, light coming up on a small stage, the companion appearing with a greeting, then a welcome line. If the 3D companion isn't ready in time it falls back to the 2D face. It honours reduced motion, has light and dark staging, and Enter continues with Back available.
- <a id="on-03"></a>✅ **Browser import step.** The same flow as [ST-46](#st-46), with an explainer of what comes over and that the other browser is left untouched. Results distinguish success, partial, nothing found and failed.
- <a id="on-03r"></a>✅ **Recommended extensions in setup.** The browser import step carries the extension choice from [ST-46 X](#st-46x) and, below the password import, a compact Recommended shelf from [ST-40 R](#st-40r) with the same Add, Installed and Set up states.
- <a id="on-04"></a>✅ **Import from the system password app.** For people coming from the system browser, a guided three-step flow opens the macOS password app, explains how to export a CSV, and then lets you pick the file. Atelier imports it into the vault, reports the count (or none, or incomplete), offers to delete the CSV, and can be skipped.
- <a id="on-05"></a>✅ **Name suggestions.** Beside the name field, a few clickable suggestions from a built-in list of short names, with a reshuffle button. The name carries into the rest of setup.
- <a id="on-06"></a>✅ **Setup questions.** The companion asks one card at a time: free text (typed or dictated), single or multiple choice with an other option, confirm-or-correct, information, and chips to start with a tool. - <a id="on-10"></a>✅ **Import past AI conversations.** Pick one or more conversation exports from other assistants. After a preparing state, Atelier imports them into chats ([CH-31](#ch-31)) and memory in the background and shows a count, with continue and skip.
- <a id="on-11"></a>✅ **Launch step.** The last step opens the main window on the first chat page, seeded from the setup answers. If that fails, it offers try again or just open the browser. Atelier doesn't edit the Dock itself; a tip explains how to keep it there.
- <a id="on-12"></a>✅ **Getting-started checklist storage.** A getting-started record (`userData/first-week.json`) is created when setup finishes, stored as a versioned local file and schema-checked on load. The checklist can be switched off (hiding it), and its state is always one of off, not created yet, invalid (reset, notice not yet seen) or ready.
- <a id="on-13"></a>✅ **Getting-started checklist items.** First steps: up to eight starter chats, written once by a small model call from what Atelier already knows (your name, the companion's standing instructions, memory notes, connected connectors, recent pages) when a key is set, and cached; without a key, or when the call fails, Atelier's curated list is used. Each opens a new chat with the active companion, its prompt already sent. Starter chats are self-serve: opening one ticks it off, and its menu marks it done or not done by hand. Items can be put aside one by one (with undo), dismiss all unlocks 30 days after setup, snooze hides the checklist until 9:00 the next local day, and hiding records why (a reason and an optional local note).
- <a id="on-15"></a>✅ **Getting-started page.** atelier://first-week, one centred column: a hero banner in the companion's colour over the ambient field, with Atelier's mark, a heading, a two-line intro in the companion's voice and the live full-body companion ([CO-19](#co-19)); the checklist as a two-column grid of compact cards (six, then show more or less with the count); a page menu with snooze, dismiss all and hide; and the guides as large animated previews with a play control and a duration badge. Light and dark are both designed, the hero tint follows the companion, and it opens once as a tab after setup. It stays reachable from Getting Started in the profile menu, and its tab has its own icon.
- <a id="on-16"></a>✅ **Guides page.** atelier://guides offers guides and curated bundles (a skill, a routine and suggested connectors for one goal), with category filters and search. Each has a try-it action that installs or starts it.
- <a id="on-17"></a>✅ **Help topics.** The Help menu groups topics (getting started, chats and companions, skills and routines, meetings, connectors, troubleshooting). Choosing one opens a new chat about that topic, grounded in help notes that ship with Atelier.
- <a id="on-18"></a>✅ **Setup gets to know you, and fits the workspace to you.** When an engine is connected, the questions step is a short conversation instead of cards: the companion asks one thing at a time (what you do, what you want a hand with, what you do on a rhythm, the apps you use, how hands-on you want to be), follows up on your answers, offers quick replies, and stops whenever you say. Without an engine, or when a turn fails, the cards ([ON-06](#on-06)) run instead, with a how-hands-on card and coding, data, design and projects options. Either way the answers become your profile (userData/profile.json, written to the About me memory note companions read), and a new workspace step shows what it asks for before anything is set: the sidebar rows you'll use (a technical setup keeps only chats and its routines; a simple one gets the guides), a routine for each thing you do on a rhythm (with a built-in skill when one fits), the skills that fit and the apps to connect. The connectors step ([ON-08](#on-08)) then offers those apps (and is skipped when there are none), and the showcase ([ON-09](#on-09)) shows the slides that matter to you. ## Updates

- <a id="up-01"></a>✅ **Background update checks.** States: idle, checking, downloading, ready, installing and error. Atelier checks at start-up, every few hours and on wake, retrying network failures with backoff up to five times. A download starts only after a free-space check, on your go-ahead or automatically if a setting allows it. macOS installs on quit, and the menu item's label follows the state. Releases come from GitHub through `electron-updater`, which needs signing. An unsigned macOS or Windows release build only announces: it compares its version with the latest release's feed on the same schedule, and its pill, menu items and About row open that release's page, where the person downloads the installer.
- <a id="up-02"></a>✅ **Update prompts and install.** A manual check reports up to date, couldn't check, downloading, or ready with restart now or later. When an update is ready, the sidebar's Update pill and a main-menu banner offer to install it, and a what's-new card appears after updating, in the bottom-right corner of the window in front. It stays until you close it (✕, Got it or Esc), never takes focus or blocks menus, follows the window's size, and comes back on the next window or start when Atelier closed it for you (its window closed, a quit). Installing saves pending state, shows a restart card, then quits and installs, with a watchdog and retry if the updater fails. An optional static list in the release feed can mark versions unsupported, prompting an update with a snooze that survives restarts.

## Diagnostics

Nothing here leaves the computer unless the person sends it ([OV-30](#ov-30)).

- <a id="dg-01"></a>✅ **Local logs.** Main writes its log as JSON lines (`logs/atelier.log`), rotated at 2 MB with five kept, with keys, tokens, URL queries and the home folder removed. Settings › About opens them in a viewer, and a problem report can include them.
- <a id="dg-02"></a>✅ **Helper exits are logged.** Every exit of the speech helper goes to the log with its exit code: a plain entry when Atelier asked it to quit, a warning when it stopped on its own (`captureSpeechExit` in `src/main/diagnostics/capture.ts`).
- <a id="dg-03"></a>✅ **Crash reports, opt-in.** Settings › Privacy has a crash reports switch, off by default. When on, Chromium's crash reporter keeps crash dumps on this computer (it never uploads them), and a problem report can include them. Turning it off deletes the kept reports.

## Out of scope

Atelier needs no backend to work: it leaves out what only a server could provide, and it keeps input private.

- **Accounts and billing.** Atelier runs on your own Anthropic key and keeps chats, settings and companions in the local profile ([ST-07](#st-07), [SS-05](#ss-05)).
- **Hosting and teams.** Chats, companions and packs are shared as files and links ([CH-36](#ch-36), [CO-14](#co-14), [PK-11](#pk-11), [PK-12](#pk-12)); there are no team workspaces.
- **Input history and monitoring.** Ordinary form fields keep no history (password, card and address fill cover forms), and the keyboard is never monitored system-wide: hold-to-talk works inside Atelier, and an opt-in shortcut opens the launcher from other apps ([MV-01](#mv-01), [MV-02](#mv-02)).
